# Instance Status Checks y Auto Recovery

Todas las instancias de EC2 tienen dos niveles de **verificación de estado** (status checks) por instancia. Cuando lanzás una instancia por primera vez, es posible que aparezca en la lista como "inicializando" (*initializing*), pero con el tiempo debería pasar a mostrar **2/2 checks passed**, lo que indica que todo está bien dentro de esa instancia. Si no llega a ese estado, tenés un problema.

Cada uno de los dos checks representa un conjunto separado de pruebas, y el fallo de cualquiera de ellos indica un problema distinto:

| Check | Qué valida | Un fallo sugiere |
|---|---|---|
| **System Status** | El servicio EC2 y el **host físico** subyacente | Pérdida de energía, pérdida de conectividad de red, problemas de hardware o software a nivel del host |
| **Instance Status** | La **propia instancia** | File system corrupto, configuración de red incorrecta dentro de la instancia |

El primer check, **System Status**, se enfoca en problemas que afectan al servicio de EC2 o al host EC2 subyacente, **no** a tu instancia en particular. El segundo, **Instance Status**, es lo contrario: el problema está adentro.

### Auto Recovery

Ante un fallo, se podría reiniciar la instancia, detenerla y volver a iniciarla, o volver a montar sus volúmenes, pero EC2 también trae una opción para **recuperarse automáticamente** ante problemas de System Status check. Podés configurar la instancia para que, ante una falla, EC2 la detenga, la reinicie, la termine, o realice una **recuperación automática** (auto-recovery).

La recuperación automática **mueve la instancia a un host nuevo** y la reinicia con exactamente la misma configuración que tenía antes: se mantienen todas las direcciones IP, y si el software de la instancia está configurado para iniciarse automáticamente al bootear, la instancia se recupera sola de cualquier problema de verificación de estado sin que tengas que intervenir manualmente.

> [!info] Actualización posterior al curso
> El curso presenta el auto-recovery como algo que **hay que configurar**. Desde **marzo de 2022** AWS lo habilita **por defecto** en la mayoría de los instance types modernos: ante un fallo de System Status check, la instancia se recupera sola sin que hayas creado ninguna alarma. La configuración manual (vía alarma de CloudWatch) sigue existiendo y sirve para desactivarlo o para elegir otra acción.

> [!warning] Ojo con el instance store
> El auto-recovery mueve la instancia a **otro host**, así que se aplica la regla de siempre: los datos del **instance store se pierden** (ver [[06.09 Instance Store Volumes|Instance Store Volumes]]). Por eso el auto-recovery no está disponible para instancias con instance store como almacenamiento principal.
