# Network Interfaces (ENI), IPs y DNS

### La interfaz de red (ENI)

Toda instancia EC2 arranca con una **interfaz de red**, la **ENI (Elastic Network Interface)**. Cada instancia tiene al menos una, la **primary ENI**. Opcionalmente podés adjuntarle una o más **ENIs secundarias**, que incluso pueden estar en subnets distintas — pero **todas dentro de la misma AZ** (recordá que EC2 está aislado por AZ, ver [[06.02 EC2 Architecture and Resilience#No se puede cruzar de AZ|No se puede cruzar de AZ]]).

Detalle conceptual importante: en la consola muchas cosas se muestran como si estuvieran pegadas a la **instancia** (direcciones IP, nombres DNS), pero en realidad viven en la **primary ENI**. El caso más claro son los **security groups**: cuando lanzás una instancia con security groups, esos SGs se aplican a la **interfaz de red**, no a la instancia.

### Qué tiene una ENI (sus atributos)

Cada ENI tiene una **MAC address** propia.

En cuanto a direcciones IP (donde más gente se marea), va el zoológico completo. Cada ENI tiene **una IPv4 privada principal (primary)**, tomada del rango de la subnet donde se creó la interfaz. De hecho, cuando elegís una VPC y una subnet para tu instancia, en realidad estás eligiendo la VPC y la subnet de la **primary ENI**. Además puede tener **cero o más IPv4 privadas secundarias**, **cero o una IPv4 pública**, **una Elastic IP por cada IP privada** de la interfaz, y **cero o más IPv6**. Un detalle de IPv6: son **enrutables públicamente por defecto** — en IPv6 no existe la distinción público/privado, todas las direcciones son públicas.

| Tipo de dirección | Cuántas por ENI | Pública / privada | Notas clave |
|---|---|---|---|
| IPv4 privada principal | 1 (obligatoria) | Privada | Estática; no cambia nunca |
| IPv4 privada secundaria | 0 o más | Privada | — |
| IPv4 pública | 0 o 1 | Pública | **Dinámica**: cambia con stop/start (no con reboot) |
| Elastic IP | 1 por cada IP privada | Pública | **Fija**; es de tu cuenta; en la primary ENI reemplaza a la IPv4 pública normal |
| IPv6 | 0 o más | Siempre pública | En IPv6 no hay distinción público/privado |

También tiene **security groups**, aplicados **a la interfaz** (no a la instancia). Un SG aplicado a una ENI afecta a **todas las IPs de esa interfaz**.

Por último, cada ENI tiene una opción de **source/destination check** (comprobación de origen y destino). Si está **activada**, la interfaz **descarta** cualquier tráfico cuyo origen no sea una de las IPs de la interfaz, o cuyo destino no sea una de ellas. Esto es importante para las **NAT instances**: para que una EC2 instance funcione como NAT hay que **desactivar** este chequeo (una NAT justamente reenvía tráfico que no es ni de ella ni para ella misma). Ver [[05.08 Network Address Translation (NAT) y NAT Gateway|NAT y NAT Gateway]].

Cuántas ENIs secundarias podés tener depende del **tipo de instancia**.

### Cómo se comportan las IPs y el DNS (con ejemplo)

Supongamos que a la instancia le asignaron la IPv4 privada principal **10.16.0.10**. Es **estática**: no cambia en todo el ciclo de vida de la instancia. Asociado a esa IP privada, la instancia recibe un **nombre DNS privado** con formato lógico, del estilo `ip-10-16-0-10.ec2.internal`. Ese nombre **solo se resuelve dentro de la VPC** y siempre apunta a la IP privada, así que se usa para **comunicaciones internas** dentro de la VPC.

Si la instancia está configurada para recibir una **IPv4 pública** (porque la configuraste así o porque la lanzaste en una subnet que auto-asigna IPs públicas), va a recibir una. Pero es **dinámica, no fija**: si hacés **stop + start**, cambia (al detener la instancia la IP pública se libera, y al iniciarla de nuevo se le asigna otra distinta). Un **reboot no la cambia**. Es la misma idea del ciclo de vida de las instancias.

La instancia también recibe un **nombre DNS público**, con formato parecido a `ec2-3-89-7-136.compute-1.amazonaws.com` (donde la IP sería, por ejemplo, 3.89.7.136).

> [!tip] Cae en el examen: DNS split-horizon
> El nombre DNS público hace **resolución "split-horizon"** (doble cara):
> - **Dentro de la VPC** → resuelve a la **IPv4 privada principal**.
> - **Fuera de la VPC** → resuelve a la **IPv4 pública**.
>
> ¿Por qué? Porque esa IP pública **no está pegada** a la instancia ni a sus interfaces: está *asociada*, y es el **internet gateway (IGW)** el que hace la traducción (ver [[05.04 VPC Routing e Internet Gateway#Internet Gateway|Internet Gateway]]). Esto permite usar **un mismo nombre DNS** para llegar a la instancia y que el tráfico viaje por la **IP privada dentro de la VPC** (y por la pública desde afuera). Se vuelve clave con las **redes híbridas**: un nombre DNS único que resuelve a una dirección interna dentro de AWS y a una externa fuera de AWS, simplificando la "descubribilidad".
