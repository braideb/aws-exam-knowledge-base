# EC2 Instance Types

Existen distintos **instance types** en EC2. Al elegir un instance type y un tamaño (**size**) obtenés un control granular sobre la configuración de recursos de tu máquina. Esa decisión puede marcar la diferencia entre un sistema con buen rendimiento y uno que da mala experiencia al usuario, así que la idea es conocer los puntos fuertes y débiles de cada tipo y no elegir a ciegas.

Cuando elegís un instance type estás definiendo varias cosas a la vez:

- **Cantidad bruta de recursos:** vCPU, memoria, capacidad de almacenamiento local y el tipo de ese almacenamiento.
- **Proporciones (resource ratios) entre esos recursos:** algunos types te dan más de un recurso y menos de otro según el tipo de aplicación. Por ejemplo, uno puede darte mucha CPU y poca memoria, mientras que otro pensado para caché en memoria prioriza la memoria y te da mucha por cada dólar gastado.
- **Costo por minuto:** el type y el size influyen directamente en el precio.
- **Ancho de banda de red** (para datos y para almacenamiento). Esto es muy relevante con **Elastic Block Store (EBS)**, que es almacenamiento **basado en red**: podés aprovisionar volúmenes EBS de rendimiento muy alto, pero si la instancia no ofrece suficiente ancho de banda de red para almacenamiento, **la propia instancia se convierte en el cuello de botella**. Por eso existe el término **EBS-optimized**: instancias con ancho de banda de red dedicado para EBS.
- **Arquitectura de hardware y fabricante:** por ejemplo **ARM** vs **x86**, o CPUs **Intel** vs **AMD**.
- **Características y capacidades extra:** como una **GPU** para procesamiento gráfico o una **FPGA** (chip reprogramable para tareas específicas).

> [!note] El cuello de botella por instancia, más adelante
> Ese tope de ancho de banda hacia EBS es el mismo "límite por instancia" que reaparece con los volúmenes de alto rendimiento — ver [[06.07 EBS Volume Types - Provisioned IOPS SSD (io1, io2, Block Express)#El tope por instancia (per-instance)|El tope por instancia]].

### Las cinco categorías principales

Las instancias de EC2 se agrupan en cinco categorías principales, que ayudan a elegir según el tipo de carga de trabajo (workload):

- **General Purpose:** categoría por defecto y casi siempre el punto de partida. Pensada para cargas de estado estacionario (steady-state), con una proporción de recursos bastante pareja (CPU y memoria acompañadas). Solo te alejás de acá si tenés un requisito específico que lo justifique.
- **Compute Optimized:** para tareas que exigen mucho procesamiento (media processing, HPC —high-performance computing—, modelado científico, gaming, machine learning). Da acceso a las CPUs de alto rendimiento más recientes y, en general, ofrece más CPU que memoria para un precio dado.
- **Memory Optimized:** lo contrario, grandes cantidades de memoria por cada dólar (o por cada unidad de CPU). Ideal para trabajar con grandes conjuntos de datos en memoria, como caché en memoria o ciertas cargas de base de datos.
- **Accelerated Computing:** donde entran las capacidades extra —**GPUs** dedicadas para procesamiento y modelado paralelo a gran escala, o hardware programable a medida como las **FPGAs**. Casos de nicho, pero si los necesitás lo vas a saber.
- **Storage Optimized:** grandes cantidades de almacenamiento local ultrarrápido, optimizado para altas tasas de transferencia secuencial o para entregar enormes cantidades de **IOPS**. Bueno para aplicaciones exigentes en I/O secuencial o aleatorio (data warehousing, Elasticsearch, cargas analíticas).

### El esquema de nombres de un instance type

El nombre de un instance type codifica varias cosas. Tomando el ejemplo **R5dn.8xlarge**:

- **R** → **Instance Family** (la familia; en este caso, Memory Optimized).
- **5** → **Instance Generation** (la generación; conviene usar la más nueva disponible).
- **dn** → **Additional Capabilities** (capacidades adicionales, por ejemplo NVMe local y networking mejorado).
- **8xlarge** → **Instance Size** (el tamaño).

El conjunto completo (`R5dn.8xlarge`) es el **Instance Type**.
