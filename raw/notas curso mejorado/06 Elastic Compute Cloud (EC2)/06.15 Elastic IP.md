# Elastic IP

Una **Elastic IP** es una IPv4 pública fija que AWS asigna a tu **cuenta**, no a una instancia en particular. La IP "vive" en tu cuenta como un recurso independiente, y vos decidís a qué la asociás.

El flujo normal: primero hacés el **allocate** (AWS te reserva una Elastic IP) y después la **asociás** a una IP privada de una instancia. Esa IP privada puede estar en la **primary ENI** o en una ENI secundaria (si la instancia tiene más de una).

### Puntos que suelen aparecer en el examen

- Si asociás una Elastic IP a la interfaz de red **principal** de una instancia, la IP pública "normal" que ya tenía (la dinámica, no-elástica) **se elimina**, y la Elastic IP pasa a ocupar su lugar como nueva IP pública.
- Si después **desasociás** esa Elastic IP, la instancia no se queda sin IP pública: automáticamente le asignan una nueva IP pública dinámica.

La idea de fondo: una instancia normal, sin Elastic IP, tiene una IP pública que **cambia** con cada stop/start (ver [[06.14 Network Interfaces (ENI), IPs y DNS#Cómo se comportan las IPs y el DNS (con ejemplo)|cómo se comportan las IPs]]). Eso es un problema si necesitás que la IP sea siempre la misma (apuntar un dominio, whitelistear una IP en un firewall externo). La Elastic IP resuelve eso: te da una IP pública que no cambia, sin importar cuántas veces reinicies la instancia, mientras la Elastic IP siga asociada.

> [!tip] También lo preguntan
> AWS **cobra por una Elastic IP que no está en uso** (asignada pero no asociada a ninguna instancia, o asociada a una instancia detenida). La lógica es desalentar que la gente reserve IPv4 públicas —un recurso escaso— y las deje sin usar.

> [!info] Actualización posterior al curso
> Desde **febrero de 2024** AWS cobra por **toda IPv4 pública**, esté en uso o no: la Elastic IP asociada a una instancia corriendo también se factura, igual que la IPv4 pública dinámica que se auto-asigna. El razonamiento del curso (desalentar el acaparamiento de un recurso escaso) sigue siendo el correcto, pero **ya no hay una IPv4 pública gratis**. Consecuencia práctica: hoy conviene evitar asignar IPs públicas cuando alcanza con salir por un [[05.08 Network Address Translation (NAT) y NAT Gateway|NAT Gateway]] o llegar por [[05.09 VPC Endpoints|VPC Endpoints]].
