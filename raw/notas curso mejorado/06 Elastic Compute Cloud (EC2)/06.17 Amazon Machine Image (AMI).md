# Amazon Machine Image (AMI)

> [!note] Los fundamentos ya están en el módulo 01
> [[01.06 Amazon Machine Image (AMI)|01.06 Amazon Machine Image (AMI)]] cubre qué es una AMI por dentro (metadata + snapshots de EBS), los tres **permisos** (public / owner implícito / explicit), el **root volume**, el **block device mapping** y el hecho de que las AMIs son **regionales**. Esta sección no repite nada de eso: agrega las **fuentes** de AMIs, su **costo**, el **ciclo de vida** y el **AMI baking**.

Las **AMI** son las imágenes de EC2: una forma de crear una plantilla con la configuración de una instancia para después lanzar muchas instancias a partir de esa misma configuración.

En realidad las usás todo el tiempo sin darte cuenta: cada vez que lanzás una instancia, la lanzás a partir de una AMI. Por defecto usás las que provee AWS (por ejemplo, la AMI de Amazon Linux de la [[06.16 Demostración - Instalación manual de WordPress|demo de WordPress]]), pero también podés crear las tuyas.

### De dónde salen las AMIs, y qué cuestan

- Las AMI pueden venir de distintas fuentes: **AWS**, la **comunidad** o el **Marketplace**.
- Las del **Marketplace** suelen incluir software comercial ya instalado y configurado (un firewall de un fabricante, un CMS con licencia, etc.). Al lanzar una instancia con una de estas AMI, pagás la tarifa normal por hora de la instancia **más** un cargo adicional por el software con licencia. Es decir: **costo total = costo de la instancia (cómputo) + costo de la AMI (licencia del software)**. Se lanza igual que cualquier otra, solo que la elegís desde el Marketplace.
- Podés **crear una AMI a partir de una instancia** ya configurada como querés. Esto captura ese estado (OS, software instalado, archivos de configuración) como plantilla reutilizable, y así no repetís manualmente la instalación cada vez.

### AMI Lifecycle (ciclo de vida)

Cuatro fases:

1. **Launch** — lanzás una instancia a partir de una AMI base (por ejemplo, una AMI estándar de Amazon Linux).
2. **Configure** — instalás y configurás todo lo que necesitás sobre esa instancia, dejándola en el estado exacto a replicar.
3. **Create image** — creás una nueva AMI a partir de esa instancia. Captura una "foto" del estado actual (incluyendo los discos, vía **snapshots** de los volúmenes EBS, referenciados por un **Block Device Mapping**) y la convierte en plantilla reutilizable.
4. **Re-launch** — usás esa nueva AMI para lanzar todas las instancias que necesites, ya configuradas de entrada, sin repetir el paso 2.

> [!tip] AMI — puntos de examen
> - **AMI = una sola región**; solo funciona en esa región.
> - **AMI Baking**: crear una AMI desde una instancia + aplicación ya configuradas.
> - Una AMI **no se puede editar**: lanzás una instancia, actualizás la configuración y creás una AMI nueva.
> - Se puede **copiar entre regiones** (incluye sus snapshots).
> - **Permisos por defecto = tu cuenta** (privada).
