# Demostración: Instalación manual de WordPress

🔗 **Parte 1:** <https://learn.cantrill.io/courses/1101194/lectures/27806465>
🔗 **Parte 2:** <https://learn.cantrill.io/courses/1101194/lectures/27806466>

Esta demo instala, "a mano" y por línea de comandos, todo lo que WordPress necesita para funcionar sobre una instancia EC2. Son básicamente tres cosas: un servidor web (**httpd**, o sea Apache), un motor de base de datos (**MariaDB**, un fork de MySQL) y el propio código de WordPress (escrito en PHP). El objetivo no es memorizar cada comando, sino entender **qué rol cumple cada paso** en el armado de un servidor web típico.

> [!note] Por qué esta demo importa más adelante
> Todo este trabajo manual es exactamente lo que la siguiente sección evita: una vez que la instancia quedó configurada, se le saca una **AMI** y no hay que repetir nada. Ver [[06.17 Amazon Machine Image (AMI)#AMI Lifecycle (ciclo de vida)|AMI Lifecycle]].


**STEP 1 — Configurar variables de autenticación.** Se definen variables de shell reutilizables en varios comandos posteriores (evita repetir nombre de base, usuario y contraseñas, y es más prolijo si algún día lo convertís en script):

```bash
DBName='a4lwordpress'
DBUser='a4lwordpress'
DBPassword='4n1m4l$4L1f3'
DBRootPassword='4n1m4l$4L1f3'
```

- `DBName`: nombre de la base que va a usar WordPress.
- `DBUser`: usuario de MariaDB que WordPress usa para conectarse (no es root).
- `DBPassword`: contraseña de ese usuario.
- `DBRootPassword`: contraseña del usuario **root de MariaDB** (el administrador del motor de base de datos; no tiene nada que ver con el root del sistema operativo).

**STEP 2 — Instalar el software del sistema (web y base de datos):**

```bash
sudo dnf install wget php-mysqlnd httpd php-fpm php-mysqli mariadb105-server php-json php php-devel -y
```

`dnf` es el gestor de paquetes de Amazon Linux (sucesor de `yum`). Instala todo junto: `httpd` (Apache), `mariadb105-server` (motor de base de datos), `php` y sus módulos (`php-mysqli`, `php-fpm`, etc., los "puentes" que permiten a PHP hablar con Apache y con MariaDB) y `wget` (para descargar archivos por HTTP, usado más abajo).

**STEP 3 — Levantar los servicios y dejarlos configurados para iniciar automáticamente:**

```bash
sudo systemctl enable httpd
sudo systemctl enable mariadb
sudo systemctl start httpd
sudo systemctl start mariadb
```

`systemctl` administra servicios en Linux. `enable` hace que el servicio arranque solo en cada boot (si reiniciás la instancia sin `enable`, el servidor web no vuelve a levantar solo). `start` arranca el servicio ahora mismo.

**STEP 4 — Configurar la contraseña root de MariaDB:**

```bash
sudo mysqladmin -u root password $DBRootPassword
```

Acá hace falta el `$` antes de `DBRootPassword` (la shell reemplaza la variable por su valor). Le pone contraseña al usuario root de MariaDB (recién instalado no tiene).

**STEP 5 — Descargar e instalar WordPress:**

```bash
sudo wget http://wordpress.org/latest.tar.gz -P /var/www/html
cd /var/www/html
sudo tar -zxvf latest.tar.gz
sudo cp -rvf wordpress/* .
sudo rm -R wordpress
sudo rm latest.tar.gz
```

`/var/www/html` es la carpeta donde Apache busca por defecto los archivos del sitio. Se baja el `.tar.gz`, se descomprime (`tar -zxvf`), se copia el contenido de `wordpress/` a la raíz del sitio y se borra lo que ya no hace falta.

**STEP 6 — Configurar WordPress.** Acá estaba el error más importante: **faltaba el `$` antes de las variables** y dos líneas de `sed` quedaron sin salto de línea. Así como estaba, `sed` buscaba literalmente el texto `'DBName'` en el archivo en vez de reemplazarlo por el valor de la variable. Versión correcta:

```bash
sudo cp ./wp-config-sample.php ./wp-config.php
sudo sed -i "s/'database_name_here'/'$DBName'/g" wp-config.php
sudo sed -i "s/'username_here'/'$DBUser'/g" wp-config.php
sudo sed -i "s/'password_here'/'$DBPassword'/g" wp-config.php
sudo chown apache:apache * -R
```

`wp-config.php` es donde WordPress guarda los datos de conexión a la base. Viene con valores de ejemplo (`database_name_here`, etc.) y `sed` busca y reemplaza texto dentro del archivo, línea por línea, sin abrirlo en un editor. La última línea, `chown apache:apache * -R`, cambia el dueño de todos los archivos (recursivo, `-R`) al usuario `apache`, con el que corre el servidor web; es necesario porque, si quedan como propiedad de `root` (por usar `sudo`), Apache no tendría permisos para leerlos ni escribirlos.

**STEP 7 — Crear la base de datos de WordPress.** Mismo problema de transcripción (faltaban `$` y saltos de línea). Versión corregida:

```bash
echo "CREATE DATABASE $DBName;" >> /tmp/db.setup
echo "CREATE USER '$DBUser'@'localhost' IDENTIFIED BY '$DBPassword';" >> /tmp/db.setup
echo "GRANT ALL ON $DBName.* TO '$DBUser'@'localhost';" >> /tmp/db.setup
echo "FLUSH PRIVILEGES;" >> /tmp/db.setup
mysql -u root --password=$DBRootPassword < /tmp/db.setup
sudo rm /tmp/db.setup
```

La lógica: en vez de entrar a la consola de MariaDB y tipear los comandos SQL uno por uno, se arma un archivo de texto (`/tmp/db.setup`) con todas las sentencias (crear la base, crear el usuario, darle permisos sobre esa base y recargar privilegios) y se le pasa entero a `mysql` de una vez con `<`. Al final se borra el archivo temporal, que además tiene la contraseña en texto plano.

**STEP 8 — Verificar.** Con todo instalado, entrás por el navegador a la IP pública de la instancia y debería aparecer el instalador de WordPress (idioma, título del sitio, usuario admin, etc.):

```text
http://your_instance_public_ipv4_ip
```
