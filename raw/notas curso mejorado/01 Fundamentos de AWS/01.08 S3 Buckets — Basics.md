# S3 Buckets — Basics

**S3** (Simple Storage Service) es una plataforma de almacenamiento **global**: funciona desde todas las regiones de AWS y se puede acceder a él desde cualquier conexión a internet.

Sin embargo, es **region-based**: los datos se almacenan en una region específica de AWS y **nunca salen de ahí** salvo que se configure explícitamente lo contrario.

Esa doble naturaleza (namespace global / datos regionales) es la fuente de casi toda la confusión con S3. Ver la nota más abajo sobre por qué el nombre es global.

### Características

- **Region resilient**: los datos se replican entre todas las AZs de la region. Soporta fallas de AZ.
- Soporta configurar **replicación entre regiones** (Cross-Region Replication), lo que permite conmutar a otra region si una falla.
- Es un **servicio público**: se puede acceder desde cualquier lugar; opera desde la AWS Public Zone.
- Perfecto para almacenar **grandes cantidades de datos de cualquier tipo**. Escala desde cero hasta niveles ilimitados.
- Económico y accesible desde **consola / CLI / API / HTTP**.
- Durabilidad de **99.999999999% (11 nueves)**: estadísticamente, si guardás 10 millones de objetos, esperarías perder uno cada 10.000 años. La **disponibilidad** es otra cosa (99.99% en Standard) — durabilidad = "no se pierde"; disponibilidad = "puedo llegar a él ahora".

> [!info] Blast radius
> El **blast radius** de un bucket de S3 es la **region**. Si la region entera se cae, se cae el bucket (salvo que tengas replicación cross-region configurada).

### Objects y Buckets

S3 almacena **objects** dentro de **buckets**:

- **Object** = el dato que se guarda.
- **Bucket** = el contenedor de objects.

Un object se compone de:

|Componente|Descripción|
|---|---|
|**Key**|El nombre del object. Ej: `koala.jpg`|
|**Value**|El contenido que se almacena. Desde **0 bytes hasta 5 TB**.|

> [!important] Flat structure
> El bucket tiene una **estructura plana (flat structure)**. No hay carpetas reales: `/old/Koala1.jpg` es simplemente una **key** que contiene barras. La consola de AWS _muestra_ eso como una carpeta llamada `old`, pero por debajo es un solo nivel. Ese "prefijo" (`old/`) es solo parte del nombre de la key.
**Por qué esto importa en la práctica**:

- **Renombrar una "carpeta" no existe**: hay que copiar cada objeto a la nueva key y borrar el viejo. Mover 1 millón de objetos = 1 millón de operaciones.
- **Listar es caro**: `ListObjects` con un prefijo grande recorre las keys. Por eso los diseños buenos usan prefijos que permitan filtrar (`logs/2026/07/22/...`).
- **Los prefijos determinan la performance**: S3 soporta **3.500 PUT/COPY/POST/DELETE y 5.500 GET/HEAD por segundo por prefijo**. Si necesitás más throughput, se reparte la carga entre varios prefijos.

### Resumen útil para el examen

- Los **nombres de los buckets son únicos a nivel global** (no por region ni por cuenta, como pasa con casi todo el resto de AWS).
- Deben empezar con **letra minúscula o número**.
- Entre **3 y 63 caracteres**, todo en minúscula, **sin underscores**. Se permiten guiones y puntos (los puntos rompen HTTPS con el certificado wildcard, así que en la práctica: **solo guiones**).
- **No pueden tener formato de dirección IP**.
- **100 buckets por cuenta** por defecto (límite _soft_: se puede subir hasta **1.000** solicitándolo a AWS).
- **Key = name**, **Value = data**.

**Por qué el nombre es global aunque los datos sean regionales** Suena contradictorio: los datos viven en una region, pero el nombre es único mundialmente. La razón es que S3 puede exponer el bucket vía **DNS** (`bucket.s3.amazonaws.com`), y el DNS es global → el nombre tiene que ser único en todo el planeta. Por eso los nombres "lindos" ya están tomados y conviene prefijarlos (ej: `miempresa-logs-prod-euwest1`).

**Límites y números que conviene tener a mano**

|Cosa|Valor|
|---|---|
|Tamaño máximo de un object|**5 TB**|
|Tamaño máximo de un solo PUT|**5 GB** (más que eso → **multipart upload** obligatorio)|
|Multipart recomendado a partir de|~100 MB|
|Objects por bucket|Ilimitados|
|Buckets por cuenta|100 (soft) / 1.000|
|AZs de replicación|≥ 3|
|Durabilidad|11 nueves|
