# Elastic Compute Cloud (EC2) — Basics

**EC2 es IaaS** (Infrastructure as a Service). Proporciona acceso a máquinas virtuales llamadas **instancias EC2**.

Es IaaS porque la unidad de consumo es la **instancia**, y una instancia es un sistema operativo configurado de determinada manera, con un conjunto de recursos asignados. AWS te da la máquina prendida y con red; de ahí para arriba, es todo tuyo.

**EC2 es el "default compute" del examen** Regla mental de Cantrill: EC2 es la opción por defecto para cómputo **salvo** que haya una buena razón para otra cosa. Si el escenario menciona cargas de trabajo largas, software tradicional o monolitos, o si necesitás control del SO → EC2. Si menciona eventos, ejecuciones cortas y esporádicas, o "no quiero administrar servidores" → probablemente sea Lambda o un servicio gestionado.
### Características
- **EC2 es un servicio privado de AWS**: por defecto se ejecuta en la AWS Private Zone (dentro de una VPC).
- Las instancias se lanzan **dentro de una única subnet** de una VPC.
- Por defecto el acceso es **privado**. Si querés acceso público hay que configurarlo a mano (IP pública + IGW + route table + SG).
- Como la instancia vive en una subnet y la subnet vive en una AZ, **si falla la AZ, falla la instancia** → EC2 es **AZ resilient**.
- Al crear una instancia se eligen **size** y **capabilities**, lo que determina sus recursos (CPU, RAM, red, etc.). Estas cosas **se pueden cambiar después** de creada (pero requiere **detener** la instancia primero).
- Al ser IaaS, vos configurás el **SO y las aplicaciones**; AWS se encarga del hardware físico, la red, el almacenamiento y las instalaciones.
- Facturación **on-demand**: se paga por uso, **por segundo o por hora**, dependiendo del software que se lance con la instancia (Linux y Ubuntu: por segundo, con mínimo de 60 s; algunas AMIs comerciales de Windows/RHEL: por hora).

### Tipos de almacenamiento

Los dos más conocidos:

|              | **Instance Store** (local on-host)                                               | **EBS** (Elastic Block Store)                                                 |
| ------------ | -------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Dónde vive   | Discos físicos **en el host** donde corre la instancia                           | Volúmenes de **red**, independientes del host                                 |
| Persistencia | **Efímero**: si se detiene, migra de host o se termina, **los datos se pierden** | **Persistente**: sobrevive a stop/start y a la terminación (si lo configurás) |
| Performance  | Rapidísimo (NVMe local, sin salto de red)                                        | Muy buena, pero pasa por la red                                               |
| Costo        | Incluido en el precio de la instancia                                            | Se paga aparte, por GB/mes                                                    |
| Snapshots    | No                                                                               | Sí, se guardan en S3                                                          |
| Caso de uso  | Caché, scratch, buffers, datos replicados en otro lado                           | Casi todo: SO, bases de datos, datos que importan                             |
**El momento en que se pierde un Instance Store** Se pierden los datos si: la instancia se **detiene (stop)**, se **hiberna**, se **termina**, o si el host físico falla. **No** se pierden con un **reboot** (el reboot no cambia de host físico). Esa diferencia entre _stop_ (cambia de host → perdés instance store, perdés IP pública) y _reboot_ (mismo host → no perdés nada) es importante entenderlo, pero no ahora, si no entendes espera a las secciones de EC2, abrazo.
### Estados de una instancia

|Estado|Qué se cobra|
|---|---|
|**Running**|CPU, RAM, almacenamiento y red. **Todo.**|
|**Stopped**|Solo el **almacenamiento (EBS)**. No se cobra CPU, RAM ni red.|
|**Terminated**|**Nada.** Se libera todo (la instancia y, por defecto, su volumen raíz).|

> [!note] `Terminated` es un estado **irreversible**. Existen otros estados intermedios (`pending`, `stopping`, `shutting-down`), pero el curso no los detalla en este punto.
