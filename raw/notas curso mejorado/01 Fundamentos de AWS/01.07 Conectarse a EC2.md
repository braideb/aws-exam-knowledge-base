# Conectarse a EC2

|SO|Protocolo|Puerto|
|---|---|---|
|**Windows**|**RDP** (Remote Desktop Protocol)|`3389`|
|**Linux**|**SSH**|`22`|
Esos puertos hay que **abrirlos en el Security Group** (se explica mas adelante) de la instancia, y la instancia tiene que ser alcanzable por red (IP pública + IGW si venís de internet, o una ruta privada si venís de la VPC).
### Key pairs
Al crear una instancia EC2 se elige un **key pair**: se crea uno nuevo o se usa uno existente. El par consta de:

- **Public key** → la tiene la **instancia EC2** (AWS la inyecta en `~/.ssh/authorized_keys` del usuario por defecto).
- **Private key** → la tengo **yo** (archivo `.pem`), y la uso para conectarme.

**En Linux**: te conectás por SSH usando directamente la private key.

``` bash
chmod 400 mi-clave.pem  # obligatorio: SSH rechaza claves con permisos abiertos
ssh -i mi-clave.pem ec2-user@54.x.x.x
```

**En Windows** es distinto: hay que proporcionar la **private key** para **desencriptar la contraseña del administrador local** de la instancia. Después te conectás por **RDP** usando el usuario administrador local y esa contraseña.

**Usuario por defecto según la AMI** Un error clásico es intentar `ssh root@...` y que rebote. Cada AMI trae su usuario:

| AMI                                  | Usuario               |
| ------------------------------------ | --------------------- |
| Amazon Linux / Amazon Linux 2 / 2023 | `ec2-user`            |
| Ubuntu                               | `ubuntu`              |
| Debian                               | `admin`               |
| RHEL                                 | `ec2-user` o `root`   |
| CentOS                               | `centos` o `ec2-user` |
| SUSE                                 | `ec2-user` o `root`   |

El login directo como `root` está deshabilitado por defecto en casi todas.

**Los key pairs son **regionales** y AWS no guarda la privada**

- Un key pair creado en `us-east-1` **no existe** en `sa-east-1`. Hay que crear/importar uno en cada region.
- AWS guarda **solo la clave pública**. La privada se descarga **una única vez** al crearla; si la perdés, AWS no te la puede devolver.
- **¿Perdiste la .pem y necesitás entrar?** El procedimiento clásico es: detener la instancia → desattachar el volumen raíz → attacharlo a otra instancia como volumen secundario → editar `authorized_keys` a mano → volver a attachar y arrancar. (O directamente usar Session Manager, se ve mas adelante en el curso.)
