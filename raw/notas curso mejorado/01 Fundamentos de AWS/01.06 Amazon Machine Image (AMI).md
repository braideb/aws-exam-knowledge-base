# Amazon Machine Image (AMI)

Una **AMI** es una **imagen de una instancia EC2**: la plantilla desde la que se crea. Se puede usar una AMI para crear una instancia, o crear una AMI a partir de una instancia existente. Es el equivalente a una imagen de servidor para crear máquinas virtuales.

Una AMI se ocupa de tres cosas:

### 1. Permisos
Los permisos controlan qué cuentas pueden y cuáles no pueden usar la AMI:
- **Public** — cualquiera puede usarla (así se distribuyen las AMIs oficiales de Amazon Linux, Ubuntu, etc.).
- **Owner (implicit)** — el dueño de la AMI puede crear instancias a partir de ella. Este permiso no se puede sacar.
- **Explicit** — se otorga permiso a cuentas específicas de AWS. Es el mecanismo típico para compartir una "golden AMI" entre las cuentas de una organización.

### 2. Root volume
Es el volumen donde arranca el sistema operativo. Una AMI puede tener otros volúmenes adicionales, pero **siempre tendrá al menos el de arranque**.

### 3. Block device mapping
Define qué volumen es el de arranque (boot) y cuál es el de datos, y cómo se mapean a los nombres de dispositivo dentro del SO (`/dev/xvda`, `/dev/sdb`, etc.).


> [!note] Qué es realmente una AMI por dentro
> Una AMI no es un archivo: es **metadata** que apunta a uno o más **EBS snapshots** (el root y los volúmenes de datos) + permisos + block device mapping. Por eso crear una AMI genera snapshots por detrás, y **borrar la AMI no borra automáticamente sus snapshots** (te los siguen cobrando ).

**Las AMIs son **regionales**** Una AMI existe **en una sola region** y tiene un ID único por region: la misma Amazon Linux 2023 es `ami-0abc...` en `us-east-1` y `ami-0xyz...` en `sa-east-1`. Consecuencias:
- No podés lanzar una instancia en `sa-east-1` con el ID de AMI de `us-east-1`.
- Para usarla en otra region hay que hacer **Copy AMI** (copia los snapshots por detrás, lo que genera costo de transferencia y de almacenamiento en la region destino).
- Por eso los templates de CloudFormation usan la sección **`Mappings`** o **SSM Parameters** para resolver el AMI ID correcto según la region — hardcodear un AMI ID es la forma más rápida de romper un template al cambiar de region.
