# Route 53 (R53) — Fundamentos

**Route 53** es el producto de **DNS administrado** de AWS. Ofrece dos servicios principales:
1. **Registro de dominios** (domain registration).
2. **Hospedaje de zone files** en managed name servers que responden consultas DNS.

**Resiliencia** R53 es un **servicio global** con una **única base de datos**. Es uno de los pocos servicios de AWS que funcionan como un servicio mundial único → es **globally resilient**. Además, es el único servicio de AWS con un **SLA del 100%** de disponibilidad. Tiene sentido: si el DNS se cae, no importa cuán resiliente sea el resto.

### Arquitectura de R53

R53 tiene relaciones con todos los principales **registries** de dominio, es decir, las empresas que administran los **TLD** (Top Level Domains): `.com`, `.io`, `.net`, `.org`, etc.

Una de esas relaciones es con el registry de `.org`, una organización llamada **PIR**.

Flujo al registrar un dominio (ej: `animals4life.org`):
1. R53 consulta al **registry** del TLD correspondiente (PIR, para `.org`) si el dominio está disponible.
2. Si está disponible, R53 crea un **zone file** para el dominio. Un zone file es simplemente una base de datos que contiene información DNS de un dominio en particular.
3. R53 asigna **name servers** a esa zone: toma el zone file y lo pone en servidores de nombres gestionados (**managed name servers**).
4. R53 se comunica con el registry (PIR) y **agrega registros NS** en el zone file del TLD `.org`, apuntando a esos name servers.
5. De esta forma se **delega** la autoridad del dominio: esos name servers pasan a ser **autoritativos** para `animals4life.org`.

> [!note]  Registrar (registrador) vs. Registry (registro) vs. Registrant
> Términos que el examen a veces usa para confundir:
> - **Registry**: la organización que **administra un TLD** y mantiene su base de datos maestra (PIR para `.org`, Verisign para `.com`).
> - **Registrar**: la empresa con la que **vos comprás** el dominio y que habla con el registry en tu nombre (R53 actúa como registrar).
> - **Registrant**: **vos**, el que registra/posee el dominio.
> R53 puede ser tu **registrar** Y tu **DNS hosting** a la vez, pero son dos funciones separadas: podés registrar el dominio en otro lado y usar solo el hosting de R53, o al revés.

R53 puede ser tu **registrar** Y tu **DNS hosting** a la vez, pero son dos funciones separadas: podés registrar el dominio en otro lado (GoDaddy, Namecheap) y usar solo el hosting de R53, o al revés. El caso híbrido es frecuente y aparece en escenarios: dominio comprado en otro registrar + hosted zone en R53. Lo único que hay que hacer es **cambiar los NS records en el registrar** para que apunten a los cuatro name servers que R53 te asignó.

### Hosted Zones

Una **hosted zone** es un **zone file dentro de AWS**.
- Se aloja en **cuatro managed name servers**.
- Puede ser **public** (accesible desde internet) …
- … o **private**, **linkeada a una o varias VPCs**.
- Almacena **records** (también llamados **recordsets**).
