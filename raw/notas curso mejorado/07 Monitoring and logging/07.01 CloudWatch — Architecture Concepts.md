# CloudWatch — Architecture Concepts

CloudWatch es un **servicio público** que se encarga de la **ingestion, storage y management de metrics**. Al ser público, tiene un **endpoint en la zona pública de AWS**, así que se puede acceder a él tanto desde AWS como desde entornos on-premises.

### Cómo se llega al endpoint desde una VPC

Cualquier servicio dentro de AWS que use CloudWatch necesita llegar a ese endpoint público. Hay dos caminos:

| Camino | Qué implica |
|---|---|
| **Internet Gateway** | La instancia sale a la zona pública de AWS (necesita IP pública o un NAT Gateway). |
| **Interface Endpoint** (PrivateLink) | La VPC llega al endpoint de CloudWatch de forma privada, sin salir a internet. Ver [[05.09 VPC Endpoints\|VPC Endpoints]]. |

### Integración nativa vs. CloudWatch Agent

Muchos servicios de AWS tienen **integración nativa** con CloudWatch a través del management plane. EC2, por ejemplo, envía metrics de las instancias sin que haya que configurar nada.

Pero esa integración solo cubre **lo que EC2 puede ver desde afuera de la instancia**. Para todo lo que ocurre **dentro** de la instancia (o dentro de un servicio) se usa el **CloudWatch agent**, que reporta de vuelta a CloudWatch detalles como:
- procesos en ejecución,
- uso de **memoria**,
- uso de **espacio en disco** dentro del sistema operativo.

> [!tip] Para el examen
> Cualquier cosa que conceptualmente solo sea visible **dentro del sistema operativo** de la instancia, o dentro del servicio, por lo general **requiere un agent**. El caso clásico: "no veo la métrica de memoria de mi EC2" → instalar el CloudWatch agent (con un IAM role que le permita publicar). Ver también [[01.11 CloudWatch — Basics|CloudWatch — Basics]].

### Otros orígenes de datos: on-premises y aplicaciones

CloudWatch también se puede usar desde **entornos on-premises**, ya sea con el agent o directamente con la **API**. Lo mismo vale para las **aplicaciones**: se puede integrar el producto en ellas con agents, con la API o con una combinación de ambos. En todos estos casos se generan **custom metrics**.

### Qué se hace con los datos

- Una vez dentro de CloudWatch, los datos se **almacenan de forma persistente** y se pueden ver o consultar desde la **console UI**, la **CLI** o la **API**.
- CloudWatch ofrece **dashboards** y **anomaly detection**.
- Las **alarms** reaccionan a las metrics: pueden estar en estado **OK** o **ALARM** y generar notificaciones si los datos se salen de los niveles normales. Detalle en [[07.04 CloudWatch Alarms|CloudWatch Alarms]].

### Arquitectura

El esquema de arquitectura tiene tres zonas:
- **Zona naranja:** la zona pública de AWS. Ahí se encuentra **CloudWatch**.
- **Zona verde (abajo):** las VPCs privadas.
- **Zona roja (arriba):** las instalaciones on-premises y los entornos conectados a internet.
