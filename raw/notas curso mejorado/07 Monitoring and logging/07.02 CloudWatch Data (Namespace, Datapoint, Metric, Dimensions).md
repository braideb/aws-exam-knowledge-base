# CloudWatch Data (Namespace, Datapoint, Metric, Dimensions)

Cuatro piezas que definen cómo CloudWatch organiza los datos, de la más grande a la más chica:

| Pieza | Qué es | Ejemplo |
|---|---|---|
| **Namespace** | Container de metrics | `AWS/EC2` |
| **Metric** | Serie temporal de datapoints | `CPUUtilization` |
| **Dimension** | Par name/value que separa o agrupa la metric | `InstanceId=i-111111111` |
| **Datapoint** | Una lectura individual | `42` (%) a las `08:45:45` |

### Namespace

Un **Namespace** es un **container** de metrics. Como puede haber metrics con el mismo nombre en servicios o aplicaciones diferentes, los namespaces las mantienen **separadas y aisladas**: cada metric pertenece a un único namespace. AWS los usa para separar sus distintos servicios.
- Los namespaces de AWS siempre empiezan con el prefijo `AWS/`: `AWS/EC2`, `AWS/Lambda`, `AWS/EBS`.
- Los namespaces propios **no** pueden empezar con ese prefijo (está reservado).

### Datapoint

El **Datapoint** es el componente más pequeño de CloudWatch: cada una de las lecturas individuales que CloudWatch graba y administra. Tiene:
- **Timestamp:** fecha y hora en que se tomó el valor.
- **Value:** por ejemplo, `42` (un 42% de CPU).
- **Unit of measure** (opcional): por ejemplo, `Percent`. En el diagrama de esta sección, que muestra IOPS (operaciones de entrada/salida por segundo) de un volumen de EBS, la unidad es `Count`.

### Metric

Una **Metric** es un **conjunto de datapoints ordenados en el tiempo** (*time ordered set of data points*). Ejemplos de metrics de EC2: `CPUUtilization`, `NetworkIn`, `DiskWriteBytes`.

Cada metric tiene un **MetricName** y un **Namespace**. En `CPUUtilization` de EC2, el MetricName es `CPUUtilization` y el Namespace es `AWS/EC2`.

### Dimensions

Si las metrics se identificaran solo con MetricName y Namespace, no se podrían separar los datapoints de distintas instancias EC2. Para eso están las **Dimensions**, uno de los conceptos más difíciles de CloudWatch.

Una **Dimension** es un **par name/value** que forma parte de la **identidad** de una metric. Al publicar un datapoint, además de value, timestamp y unit, se indican el Namespace, el MetricName y **cero o más dimensions** (hasta 30 por metric). Sirven para dar perspectivas alternativas sobre los datos o un acceso más granular.

En su forma más simple, las dimensions son lo que permite que `CPUUtilization` de EC2 diferencie entre instancias, con una dimension `InstanceId`:
- `CPUUtilization`, Name=`InstanceId`, Value=`i-111111111` (cat)
- `CPUUtilization`, Name=`InstanceId`, Value=`i-222222222` (dog)

Las dimensions también sirven para **agregar (aggregate)** datos. Para las metrics de CPU, AWS agrega dimensions adicionales como `AutoScalingGroupName`, `ImageId`, `InstanceId` e `InstanceType`, y con ellas se puede ver, por ejemplo, `CPUUtilization` por tipo de instancia o de todo un ASG.

> [!warning] La agregación no es universal
> Según el diagrama del curso, esta agregación por dimensions solo está disponible en **ciertas metrics de AWS**: no en todas y **no en las custom metrics**. CloudWatch no agrega por sí solo los datos de una custom metric a través de dimensions distintas; si querés un total, tenés que publicarlo vos (o usar metric math).

> [!tip] Para el examen
> Una metric se identifica por **Namespace + MetricName + Dimensions**. Cambiar una sola dimension es, para CloudWatch, **otra metric distinta**. Por eso, al publicar custom metrics con `PutMetricData`, hay que mandar siempre las mismas dimensions si se quiere que caigan en la misma serie.
