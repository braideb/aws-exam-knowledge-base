# CloudWatch Alarms

Una **alarm** reacciona a las metrics: **monitorea (watch) una metric** durante un período de tiempo y, según esos datos, queda en un estado. El estado se define comparando el value de la metric contra un **threshold** definido por el usuario, a lo largo del tiempo.

| Estado | Significado |
|---|---|
| **OK** | La metric está dentro del threshold. |
| **ALARM** | La metric cruzó el threshold el tiempo suficiente. |
| **INSUFFICIENT_DATA** | No hay datos suficientes para decidir (típico recién creada la alarm, o si la metric deja de publicar). |

> [!info] Complemento
> El curso presenta solo **OK** y **ALARM**; el tercer estado, **INSUFFICIENT_DATA**, es el que aparece al crear la alarm y cuando faltan datos. Con `treatMissingData` se decide cómo tratar esos huecos (`missing`, `notBreaching`, `breaching`, `ignore`). Ver el caso de los metric filters en [[03.12 CloudWatch Logs|CloudWatch Logs]].

Ejemplo: una alarm sobre `CPUUtilization` que se dispare si el valor supera el **50%** durante **dos períodos de 60 segundos**.

### Parámetros de una alarm

Según el diagrama del curso (alarm de ejemplo `HIGHCPU`):

| Parámetro | Qué define | En el ejemplo |
|---|---|---|
| **Period** | Duración de cada período evaluado (y la statistic que se toma) | 60 s |
| **Evaluation Periods (N)** | Cuántos períodos recientes se miran | 2 |
| **Datapoints to Alarm (M)** | Cuántos de esos N tienen que romper el threshold ("M out of N") | 2 |
| **Condition** | Comparación + threshold | `> 50%` |

> [!tip] Para el examen
> "M out of N" sirve para evitar falsos positivos por picos aislados: con **3 de 5**, un pico suelto no dispara la alarm.

### Actions

Una alarm puede tener **una o más actions**, que se ejecutan en nombre del usuario cuando **cambia de estado**. Por ejemplo:
- Enviar una notificación a un **SNS topic**.
- Disparar una **auto scaling policy**.
- Usar **EventBridge** para iniciar una ejecución basada en eventos.
- **EC2 actions** (stop / terminate / reboot / recover), como en [[06.22 Instance Status Checks y Auto Recovery|Auto Recovery]].

### Alarm Resolution

La **resolution de la metric** limita la resolution de las alarms que la usan (ver [[07.03 CloudWatch — Resolution, Retention y Statistics|Resolution]]):
- Sobre una metric de **high resolution**, la alarm puede ser una **high resolution alarm**, con un período de **10 o 30 segundos**.
- También se puede configurar una **alarm normal**, con un período que sea cualquier **múltiplo de 60 segundos**.
- Sobre una metric de standard resolution no se puede crear una alarm de menos de 60 segundos.

> [!tip] Para el examen
> Si la pregunta pide "reaccionar en menos de un minuto" → hace falta una **custom metric de high resolution** + una **high resolution alarm** (10 s o 30 s). Tiene un costo mayor.
