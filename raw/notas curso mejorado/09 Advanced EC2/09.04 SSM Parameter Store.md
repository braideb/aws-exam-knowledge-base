# AWS Systems Manager (SSM) Parameter Store

> [!note] Resumen de la lección
> SSM Parameter Store es parte de Systems Manager y sirve para guardar y leer parámetros de tipo String, StringList o SecureString. Soporta cifrado integrado con KMS y versionado, y se protege con IAM. Se integra de forma nativa con muchos servicios de AWS, y se puede usar con la CLI o las APIs desde cualquier lugar con acceso a los public endpoints de AWS.

El **Parameter Store** permite crear **parámetros**, que tienen un **nombre** y un **valor** (el valor es donde se guarda la configuración). Muchos servicios de AWS se integran con él de forma nativa: CloudFormation tiene integraciones que ya usaste, y también lo vas a usar con la CLI desde una instancia EC2 para leer configuración.

### Tipos de parámetros

| Tipo | Para qué |
|---|---|
| **String** | Texto plano: connection strings, usuarios de base de datos, hostnames, puertos |
| **StringList** | Lista de valores separados por coma |
| **SecureString** | Texto **cifrado con KMS**: contraseñas u otra información confidencial |

Se pueden guardar cosas como códigos de licencia, connection strings de bases de datos, hostnames, puertos, configuraciones enteras y contraseñas. Además:

- Admite una **estructura jerárquica** (ver abajo).
- Guarda **distintas versiones** de cada parámetro: así como S3 tiene versionado de objetos, acá hay versionado de parámetros.

### SecureString y KMS

Con **SecureString** el parámetro se cifra con [[04.05 KMS (Key Management Service)|KMS]], así que además de los permisos sobre el parámetro **también necesitás permisos sobre KMS**: es una capa de seguridad adicional.

> [!tip] Para el examen
> Para leer el valor **descifrado** de un SecureString se pide con **`--with-decryption`**, y hacen falta **dos permisos**: el del parámetro (SSM) y el de la **CMK de KMS** que lo cifra.

> [!note] Nombres de KMS
> En la documentación actual, "CMK" (customer master key) se llama **KMS key**. En el examen pueden aparecer los dos nombres.

### Tiers

| Tier | Costo | Cantidad | Tamaño del valor | Extras |
|---|---|---|---|---|
| **Standard** | Gratis | Hasta **10.000** parámetros | Hasta **4 KB** | — |
| **Advanced** | De pago | — | Hasta **8 KB** | **Parameter policies** (por ejemplo, expiración) |

Además, Parameter Store puede **referenciar secretos de Secrets Manager** con el prefijo `/aws/reference/secretsmanager/`.

### Parámetros públicos

También existen los **parámetros públicos**: los crea AWS y están disponibles para todos. Ya los usaste en el curso. Por ejemplo, cuando creás instancias EC2 con CloudFormation sin indicar una AMI concreta, consultás un parámetro público de AWS que devuelve el **ID de la AMI más reciente** para un sistema operativo y una región.

### Arquitectura

- Es un **servicio público**: todo lo que lo use tiene que ser un servicio de AWS o tener acceso a los public endpoints de AWS.
- Lo pueden usar aplicaciones, instancias EC2 (y todo lo que corre en ellas) e incluso funciones Lambda: todos pueden pedir acceso a los parámetros.
- Como es un servicio de AWS, está muy integrado con **IAM** para los permisos: todo acceso tiene que estar **autenticado y autorizado**. Eso puede requerir credenciales de largo plazo (access keys) o, mejor, un IAM role ([[09.03 EC2 Instance Roles e Instance Profiles|instance role]]).
- Si los parámetros están cifrados, entra en juego **KMS**: hacen falta los permisos correspondientes y la CMK.

### Jerarquías

Podés crear parámetros simples o estructuras complejas y jerárquicas:

- **Simple:** `mydbpassword`, que guarda cifrada la contraseña de la base de datos.
- **Árbol:** bajo `/wordpress` pueden estar `DBUser` y `DBPassword`. Se leen por el nombre completo (`/wordpress/DBPassword`) o pidiendo **toda la rama** `/wordpress` de una vez.

Lo mismo sirve para que cada aplicación tenga su propia rama (por ejemplo `/my-cat-app`), o para dividir por equipos dentro de la organización: por ejemplo, darle al dev team una rama del árbol para guardar sus contraseñas.

### Parameter Store vs Secrets Manager

> [!tip] Para el examen: diferencia que casi siempre aparece
> Parameter Store **NO rota secretos** por sí solo. Si la pregunta pide **rotación automática** de credenciales (por ejemplo, de una base de datos RDS), la respuesta es **Secrets Manager**, que rota automáticamente con Lambda y se integra directamente con RDS. Parameter Store es la opción **barata y simple** para configuración y para secretos sin rotación.

| | Parameter Store | Secrets Manager |
|---|---|---|
| Rotación automática | ❌ | ✅ (Lambda, integración nativa con RDS) |
| Costo | Standard gratis | De pago |
| Uso típico | Configuración y secretos simples | Credenciales que tienen que rotar |
