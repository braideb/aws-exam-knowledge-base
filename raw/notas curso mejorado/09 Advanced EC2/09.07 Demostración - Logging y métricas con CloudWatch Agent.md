# Demostración: Logging y métricas con CloudWatch Agent

- 🔗 **Parte 1:** <https://learn.cantrill.io/courses/1101194/lectures/27895417>
- 🔗 **Parte 2:** <https://learn.cantrill.io/courses/1101194/lectures/29448612>

En esta demo se descarga e instala el CloudWatch Agent y se configura para capturar **tres archivos de log** de una instancia EC2:

- `/var/log/secure`
- `/var/log/httpd/access_log`
- `/var/log/httpd/error_log`

También se configura un **instance role** que le permite al agente **guardar esa configuración en Parameter Store** y **mandar los logs y las métricas** a CloudWatch y CloudWatch Logs.

### 1. Instalar el agente

```bash
sudo dnf install amazon-cloudwatch-agent
```

### 2. IAM role

- Crear un IAM role de tipo **EC2 Role**.
- Agregarle las managed policies **`CloudWatchAgentServerPolicy`** y **`AmazonSSMFullAccess`**.
- Llamar al role **`CloudWatchRole`**.
- Adjuntar el role a la instancia EC2 que creó el 1-click deployment.

### 3. Wizard de configuración

```bash
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-config-wizard
```

Aceptar todos los defaults hasta **default metrics**, y ahí elegir **advanced**. Después, cuando pregunte qué archivos de log monitorear:

```
1) /var/log/secure
   /var/log/secure
   /var/log/secure
   (Accept default instance ID)
   Accept the default retention option

2) /var/log/httpd/access_log
   /var/log/httpd/access_log
   /var/log/httpd/access_log
   (Accept default instance ID)
   Accept the default retention option

3) /var/log/httpd/error_log
   /var/log/httpd/error_log
   /var/log/httpd/error_log
   (Accept default instance ID)
   Accept the default retention option
```

- Responder **no** cuando pregunte si hay más logs.
- **Guardar la config en SSM** con el nombre por defecto.
- La config queda en `/opt/aws/amazon-cloudwatch-agent/bin/config.json` y también en SSM.

### 4. Bug fix y arranque del agente

```bash
# Bug Fix (these are needed else the agent won't start)
sudo mkdir -p /usr/share/collectd/
sudo touch /usr/share/collectd/types.db

# Load Config and start agent
sudo /opt/aws/amazon-cloudwatch-agent/bin/amazon-cloudwatch-agent-ctl -a fetch-config -m ec2 -c ssm:AmazonCloudWatch-linux -s
```

### Qué hace cada bloque

| Bloque | Qué pasa |
|---|---|
| `dnf install amazon-cloudwatch-agent` | Instala el unified CloudWatch Agent en la instancia. |
| IAM role `CloudWatchRole` | `CloudWatchAgentServerPolicy` permite mandar métricas y logs a CloudWatch. `AmazonSSMFullAccess` permite guardar y leer la config en Parameter Store. |
| `config-wizard` | Arma la configuración del agente de forma interactiva. Cada archivo de log termina en **su propio log group**, con un **log stream por instance ID**. |
| Bug fix de `collectd` | Crea el archivo `types.db` que el agente espera encontrar. Sin él, el agente no arranca. |
| `amazon-cloudwatch-agent-ctl -a fetch-config -m ec2 -c ssm:AmazonCloudWatch-linux -s` | `-a fetch-config`: carga la configuración. `-m ec2`: modo EC2. `-c ssm:<nombre>`: toma la config **desde Parameter Store**. `-s`: arranca el agente. |

### Cleanup

- Borrar el stack de CloudFormation.
- El valor de SSM Parameter Store se puede dejar.
- Borrar los log groups de CloudWatch de `/var/log/secure`, `/var/log/httpd/access_log` y `/var/log/httpd/error_log`.
- Borrar el instance role `CloudWatchRole`.
