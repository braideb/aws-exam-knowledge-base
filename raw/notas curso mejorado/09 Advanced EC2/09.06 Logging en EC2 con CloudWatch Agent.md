# Logging en EC2 con CloudWatch Agent (system y application logging)

Hasta acá en el curso vimos por arriba CloudWatch y CloudWatch Logs, y sabemos que CloudWatch monitorea algunos aspectos de rendimiento y confiabilidad de EC2. Lo importante es que **solo ve las métricas disponibles desde fuera** de la instancia.

A veces hace falta monitorear **desde dentro** de la instancia, para tener los contadores de rendimiento del propio sistema operativo: por ejemplo, ver los procesos que corren o cuánta memoria usan. Son métricas del sistema operativo que desde afuera no se ven. También puede que quieras los **logs del sistema y de las aplicaciones** de la instancia.

### El interior de la instancia es opaco

> [!tip] Para el examen
> Ni **CloudWatch** ni **CloudWatch Logs** pueden capturar de forma nativa datos o logs que se generan **dentro** de una instancia EC2. Por defecto no ven el interior de la instancia: para ellos es **opaco**. Métricas como el **uso de memoria** o el **espacio en disco** requieren el agente.

Para tener esa visibilidad se usa el **CloudWatch Agent**: un software que corre dentro de la instancia EC2 (en su sistema operativo), captura los datos que ve el sistema operativo y los manda a CloudWatch y CloudWatch Logs, para que después los puedas usar y visualizar en la consola de los dos productos.

> [!note] Unified CloudWatch Agent
> El agente actual es el **unified CloudWatch Agent**, que reemplazó al viejo CloudWatch Logs agent y maneja **métricas y logs a la vez**.

Lógicamente, para funcionar el agente necesita la **configuración** y los **permisos** adecuados para enviar esos datos.

### Arquitectura

Partimos de una sola instancia EC2 (por ejemplo, la de WordPress de las demos anteriores), que sin el agente no puede mandar ningún log a CloudWatch Logs. Para resolverlo hacen falta tres cosas:

| # | Qué | Detalle |
|---|---|---|
| 1 | **Instalar el CloudWatch Agent** | Dentro de la instancia EC2. |
| 2 | **Darle configuración** | Para que sepa exactamente qué información mandar a CloudWatch y CloudWatch Logs. |
| 3 | **Darle permisos** | Con un **IAM role** adjunto a la instancia, con permisos sobre CloudWatch Logs ([[09.03 EC2 Instance Roles e Instance Profiles\|instance role]]). Nunca con credenciales de largo plazo guardadas en la instancia: es mala práctica y difícil de gestionar a escala. |

### Log groups y log streams

La configuración del agente define las **métricas** y los **logs** que se capturan. Los logs se mandan a CloudWatch organizados en **log groups**:

- **Un log group por cada archivo de log** que se quiere capturar.
- Dentro de cada log group, **un log stream por cada instancia** que envía ese log.

### A escala

Para una sola instancia se puede hacer a mano: iniciás sesión, instalás el agente, lo configurás, adjuntás el role y empieza a mandar datos. A escala hay que automatizarlo, por ejemplo con **CloudFormation**, para que cada instancia que aprovisiones ya tenga el agente configurado.

### Configuración en Parameter Store

El agente puede obtener y guardar su configuración de varias formas. Una es el **[[09.04 SSM Parameter Store|Parameter Store]]**: la configuración del agente se guarda como un parámetro. En la [[09.07 Demostración - Logging y métricas con CloudWatch Agent|demo]] no solo se instala y configura el agente, sino que también se guarda su configuración en Parameter Store.
