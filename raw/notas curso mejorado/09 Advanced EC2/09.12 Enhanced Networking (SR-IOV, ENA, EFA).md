# Enhanced Networking (SR-IOV, ENA, EFA)

El **enhanced networking** mejora el rendimiento general de red en EC2, y es **requisito** para cualquier función de alto rendimiento, como los [[09.09 Cluster Placement Groups|cluster placement groups]]. Usa una técnica llamada **SR-IOV (Single Root I/O Virtualization)**, que, a grandes rasgos, hace que la interfaz de red física de un host EC2 **conozca la virtualización** (ver [[06.01 Virtualization 101|Virtualization 101]]).

### Sin enhanced networking

Así se ve la red de un host EC2 sin enhanced networking:

![[Pasted image 20260930211436.png]]

Hay dos instancias EC2, cada una con una virtual network interface, y las dos dependen del host, que tiene **una sola interfaz de red física**. Lo clave es que esa tarjeta física **no conoce la virtualización**, así que el host tiene que hacer de intermediario y decidir qué instancia usa la tarjeta en cada momento.

Ese proceso se hace **por software**, así que es más lento y **gasta mucha CPU del host**. Cuando el host está muy cargado (de CPU o de I/O), puede haber **caídas de rendimiento, picos de latencia y variaciones en el ancho de banda**. No es un sistema eficiente.

### Con enhanced networking (SR-IOV)

![[Pasted image 20260930211447.png]]

En este modelo, las tarjetas de red físicas del host **sí conocen la virtualización**. En lugar de presentarse como una sola tarjeta física que el host tiene que gestionar, ofrecen algo que se puede pensar como **tarjetas lógicas**: varias por cada tarjeta física. Cada instancia tiene **acceso exclusivo a una tarjeta lógica** y envía datos como si tuviera su propia tarjeta física dedicada. La tarjeta física maneja todo el proceso de punta a punta **sin gastar casi CPU del host**.

### Beneficios

| Beneficio | Por qué |
|---|---|
| **Más I/O** y **menos uso de CPU del host** | La CPU del host casi no participa. Eso se traduce en **más ancho de banda** y redes mucho más rápidas, que escalan sin afectar la CPU del host. |
| **Más packets per second (PPS)** | El tráfico va directo entre la interfaz virtual de la instancia y la interfaz lógica de la tarjeta física. Ideal para aplicaciones que dependen del rendimiento de red, sobre todo las que mueven muchos paquetes chicos en una red pequeña y aislada. |
| **Baja latencia** y, sobre todo, **baja latencia constante** | El trabajo lo hace la tarjeta de red física, no la CPU del host. |

El enhanced networking viene **habilitado por defecto, o disponible sin costo**, en la mayoría de los instance types modernos de EC2. Para ver cómo se activa, revisá el link de abajo.

### Tecnologías concretas

> [!tip] Para el examen
> | Tecnología | Qué es | Velocidad |
> |---|---|---|
> | **ENA (Elastic Network Adapter)** | El adaptador de enhanced networking **actual** | Hasta **100 Gbps** |
> | **Intel 82599 VF** | El adaptador **viejo** | Hasta **10 Gbps** |
> | **EFA (Elastic Fabric Adapter)** | Network interface especial para **HPC**: aplicaciones que necesitan comunicación entre nodos de muy baja latencia (**MPI**) | — |
