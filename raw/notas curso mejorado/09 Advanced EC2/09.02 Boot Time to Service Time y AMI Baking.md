# Boot Time to Service Time y AMI Baking

Una de las preguntas que más aparecen en el examen es qué tan rápido podés poner una instancia **en servicio**. Para eso hay una métrica, el **boot time to service time**: cuánto tarda una instancia, desde que la lanzás, en estar lista para aceptar conexiones de tus clientes.

Incluye el tiempo que AWS tarda en aprovisionar la instancia EC2 **más** el tiempo de cualquier actualización, instalación o configuración de software dentro del sistema operativo. Con una AMI provista por AWS, del lanzamiento al service time suelen pasar **minutos**.

### Post-launch time

¿Y si hace falta configurar algo más? Por ejemplo, instalar una aplicación, como cuando instalaste WordPress a mano después de lanzar la instancia ([[06.16 Demostración - Instalación manual de WordPress|demo]]). Ese tiempo se llama **post-launch time**: lo que se tarda después del lanzamiento en hacer la configuración, manual o automática, hasta que la instancia está lista para el servicio. A mano puede llevar algunos minutos, o incluso varias horas en los casos más complejos.

### Cómo acortarlo

| Enfoque | Cómo funciona | Contra |
|---|---|---|
| **Bootstrapping** ([[09.01 Bootstrapping EC2 con User Data\|user data]]) | Automatiza las instalaciones después del lanzamiento y reduce el tiempo de esos pasos. | El trabajo igual se hace en cada lanzamiento. |
| **AMI baking** | Hacés el trabajo de antemano y creás una AMI que ya lo trae incorporado. **Elimina el post-launch time.** | Perdés flexibilidad de configuración, porque todo queda fijo en la AMI. |
| **Combinar ambos (lo óptimo)** | **AMI baking** para las partes que llevan mucho tiempo y **bootstrapping** para la configuración final. | — |

Ejemplo de la combinación: si un proceso es 90% instalación y 10% configuración, hacés el bake de la AMI con el 90% de instalación y resolvés el 10% de configuración final con bootstrapping. Así bajás el post-launch time, y con él el boot time to service time, sin perder la flexibilidad de configuración que da el bootstrapping.

> [!tip] Para el examen
> **Minimizar el tiempo hasta que la instancia esté en servicio** → AMI baking (o AMI baking + bootstrapping). **Mantener la flexibilidad de configuración** → bootstrapping con user data.
