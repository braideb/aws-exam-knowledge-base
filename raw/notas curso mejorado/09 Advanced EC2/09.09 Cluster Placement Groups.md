# Cluster Placement Groups

Los **cluster placement groups** se usan para conseguir **el mayor rendimiento posible** dentro de EC2.

### Best practices al crearlos

- **Lanzar todas las instancias del grupo al mismo tiempo.** Así AWS reserva de una vez la capacidad para todo lo que necesitás. Por ejemplo, si lanzás nueve instancias, AWS podría ubicarte en un lugar con capacidad para 12; si después querés duplicar la cantidad de instancias, podrías tener problemas de capacidad.
- **Usar el mismo instance type** para todas. Junto con lanzarlas a la vez, ayuda a que AWS las ubique en un lugar con capacidad suficiente para todo lo que necesitás.

### Una sola Availability Zone

Como el foco está en el rendimiento, un cluster placement group vive en **una única Availability Zone**. Al crear el grupo **no se elige la AZ**: el grupo queda fijado a la AZ donde lanzás la primera instancia (o instancias).

### Por qué es tan rápido

Las instancias de un mismo cluster placement group suelen estar en el **mismo rack** y, muchas veces, en el **mismo host EC2**. Todas tienen ancho de banda rápido y directo hacia las demás instancias del grupo.

| Métrica | Dentro del cluster PG | Normal |
|---|---|---|
| Velocidad **por stream (single-stream)** | **10 Gbps** | 5 Gbps |
| Latencia | **La más baja posible** | — |
| Packets per second (PPS) | **El máximo posible en AWS** | — |

> [!note] Ojo con el "single-stream"
> Los 10 Gbps son la velocidad de **un solo flujo** de datos sobre una sola conexión. Algunas instancias tienen redes bastante más rápidas en total, pero un único flujo siempre queda limitado a eso: 10 Gbps dentro de un cluster placement group frente a 5 Gbps fuera de él.

Para llegar a estos niveles de rendimiento hace falta usar instancias con **[[09.12 Enhanced Networking (SR-IOV, ENA, EFA)|enhanced networking]]**, que además da más ancho de banda total que el stream único de 10 Gbps.

### Contrapartida: poca resiliencia

Justamente porque las instancias están físicamente concentradas, si falla el hardware donde corren **se pueden caer todas las instancias del grupo**. Por eso los cluster placement groups **ofrecen poca resiliencia**.

### Puntos clave para el examen

> [!tip] Para el examen
> - **No pueden abarcar varias Availability Zones**: el grupo queda fijado a una AZ cuando lanzás la primera instancia.
> - **Pueden abarcar varias VPCs** (con [[05.12 VPC Peering|VPC peering]]), pero el rendimiento empeora bastante.
> - **No todos los instance types** soportan cluster placement groups. Conviene usar **el mismo instance type** (no es obligatorio) y **lanzarlas todas al mismo tiempo** (tampoco es obligatorio, pero es muy recomendable).
> - Ofrecen **10 Gbps single-stream**.
> - Casos de uso: cargas que exigen rendimiento, alta velocidad y baja latencia, como **high-performance computing (HPC)** o análisis científico de datos, que necesitan mucha velocidad entre nodos y una latencia baja y constante.
