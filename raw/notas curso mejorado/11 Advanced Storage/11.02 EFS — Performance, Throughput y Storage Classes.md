# EFS — Performance, Throughput y Storage Classes

> [!note] Resumen de la lección
> EFS se configura sobre tres ejes: el **performance mode** (General Purpose por defecto; Max I/O es legacy), el **throughput mode** (Elastic por defecto, Bursting o Provisioned) y la **storage class** (Standard, Infrequent Access y Archive, con lifecycle policies para mover datos entre ellas).

EFS soporta cómputo de AWS que corra **Linux** (EC2, EKS y otros servicios de contenedores) y también **macOS**. Del lado Developer, lo más preguntado es que **Lambda puede montar un EFS file system** (a través de un access point) para tener almacenamiento compartido y persistente entre invocaciones, más allá de los 512 MB a 10 GB de `/tmp`.

### Performance modes

EFS ofrece dos performance modes. **General Purpose** es el **predeterminado** y lo que AWS recomienda para prácticamente todos los escenarios: es ideal para casos sensibles a la latencia, como web servers, sistemas de gestión de contenido (CMS), home directories o servicios generales de archivos en Linux.

**Max I/O** se considera hoy una opción **legacy**, y AWS lo clasifica explícitamente como generación anterior. Técnicamente escala a niveles más altos de rendimiento y de operaciones agregadas por segundo que General Purpose, pero a cambio de **mayor latencia**. Podrías considerarlo en casos muy paralelos o de rendimiento exigente (big data analytics, procesamiento de medios, análisis científico), pero AWS recomienda no usarlo por defecto, y no sería raro que en el futuro se elimine del todo.

### Throughput modes

Hay tres throughput modes. **Elastic** (el predeterminado) es la opción más simple: el rendimiento escala automáticamente hacia arriba y hacia abajo según la carga, no hay nada que aprovisionar ni créditos de burst de los que preocuparse, y pagás por lo que leés y escribís.

**Bursting** funciona de forma muy similar al storage EBS gp2, con un efecto de burst: el rendimiento aumenta en función del tamaño del file system. Para ser preciso, los créditos de Bursting son de **throughput** (no de IOPS como en gp2) y escalan con el tamaño, así que un file system más grande acumula y sostiene más throughput.

**Provisioned** te permite fijar un rendimiento alto independientemente del tamaño: podés tener un file system grande, o incluso muy chico, con un rendimiento alto. La elección depende de tu carga de trabajo; Elastic es el default por su simplicidad, pero si querés control sobre el rendimiento exacto elegís Provisioned.

Un matiz: los performance modes y los throughput modes no son del todo independientes. Si elegís Elastic, el performance mode queda en General Purpose automáticamente; Max I/O solo está disponible con Bursting o Provisioned.

### Storage classes

La clase **Standard** (la predeterminada) es la que usás cuando leés y escribís los datos día a día. Si necesitás acceder a los datos con menos frecuencia, por ejemplo un par de veces por trimestre, te cuesta menos guardarlos en **Infrequent Access (IA)**. Además existe la clase **Archive**, para datos a los que se accede muy pocas veces al año (datos fríos de larga duración): es la opción más económica de EFS. Como en S3, podés usar **lifecycle policies** para mover datos automáticamente entre clases (de Standard a IA, y de IA a Archive) según el patrón de acceso.

> [!tip] Para el examen (complemento: el curso no lo menciona acá)
> **EFS Access Points** son puntos de entrada específicos por aplicación hacia un file system: imponen una **identidad POSIX** (user ID y group ID) y un **directorio raíz** propio para todo lo que pase por ese access point. Sirven para darle a cada aplicación (por ejemplo, varias funciones Lambda o contenedores) su propia vista aislada del file system, combinados con IAM policies para controlar quién usa cada access point.
>
> Dos detalles más: las lifecycle policies se basan en **días desde el último acceso** (por ejemplo, mover a IA tras 30 días sin acceso), y las clases IA y Archive tienen un **cargo de recuperación (retrieval fee)** por GB leído, por eso solo convienen para datos a los que casi no se accede.
