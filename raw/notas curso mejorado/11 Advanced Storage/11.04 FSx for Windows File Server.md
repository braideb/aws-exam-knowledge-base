# FSx for Windows File Server

> [!note] Resumen de la lección
> **FSx for Windows File Server** entrega **file shares nativos de Windows completamente gestionados**, accesibles por **SMB** e integrados con **Active Directory** (managed o self-managed). Se despliega en **Single-AZ** o **Multi-AZ** usando ENIs dentro de la VPC. Regla de examen: **EFS** para file systems compartidos en **Linux**, **FSx** para entornos **Windows**.

FSx es un producto de file system compartido, pero resuelve la implementación de una forma muy distinta a EFS. FSx for Windows File Server es uno de los componentes principales de la gama de servicios que AWS ofrece para dar soporte a entornos Windows.

Durante buena parte de la historia de AWS, el soporte para entornos Windows fue bastante malo; no parecía ser prioridad. Esto cambió con FSx for Windows File Server, que proporciona **file servers nativos de Windows completamente gestionados**, o más específicamente **file shares**: se te entregan los file shares como unidad de consumo y los servidores en sí quedan ocultos. Es similar a la arquitectura de RDS, pero en lugar de bases de datos obtenés file shares.

### Características principales

Está diseñado para **integrarse con entornos Windows**: es un file system **nativo** de Windows, no un file server emulado. Se integra con **Active Directory**, ya sea **managed** (AWS Directory Service) o **self-managed** (un AD propio corriendo en AWS o on-premises), lo cual es clave para empresas que ya tienen su propio AD.

Es resiliente y de alta disponibilidad. Se implementa en modo **Single-AZ** o **Multi-AZ**, y esa elección controla las network interfaces que se usan para acceder al producto, que son **ENIs** dentro de la VPC. Incluso en Single-AZ, el backend usa replicación dentro de esa AZ para ser resiliente a fallas de hardware; con Multi-AZ obtenés una solución de alta disponibilidad completa entre AZs. También hace una gama completa de **backups**, tanto del lado del cliente como del lado de AWS, donde podés tener backups **automáticos** y **bajo demanda (on-demand)**.

Los file systems son accesibles dentro de la VPC, pero también (y esto es lo más complejo) desde **entornos conectados** a través de VPC peering, VPN y Direct Connect físico. Si sos una empresa grande con un enlace privado dedicado a una VPC, podés acceder a los file systems de FSx por Direct Connect.

> [!tip] Para el examen: EFS o FSx
> Ante cualquier pregunta sobre file systems compartidos, buscá palabras clave relacionadas con **Windows**: "native Windows file system", "Active Directory", "integración con directory service", y las funciones avanzadas del resto de la lección. En general, **EFS** se usa para file systems compartidos en instancias EC2 **Linux**, mientras que **FSx** está dedicado a entornos **Windows**.

### Implementación típica

Tenemos una VPC a la izquierda y una red corporativa a la derecha, conectadas con Direct Connect o VPN, con personal on-premises. Dentro de la VPC hay dos AZs (A y B), y en cada una, dos subnets privadas.

FSx usa Active Directory como su user store, así que arrancás con un **directory**, que puede ser uno managed (entregado como servicio desde AWS) o uno on-premises. Esto es importante: FSx puede integrarse con **ambos** y no necesita necesariamente un AD definido dentro de Directory Service, sino que puede conectarse directamente a un Active Directory que corre on-premises. Eso significa que FSx se integra con la implementación de AD totalmente normal que ya tiene la mayoría de las grandes empresas. Se despliegue en Single-AZ o Multi-AZ, en ambos casos tiene que estar conectado a algún directorio para su user store.

Una vez desplegado, creás un **file share** y accedés a él de la forma normal de Windows, con la notación de doble barra invertida, nombre DNS y nombre del recurso: `\\fs-xxx123.animals4life.org\catpics` (en este ejemplo, `catpics` es lo compartido). Usando esa ruta, también pueden acceder al file system otros servicios de AWS que usan almacenamiento basado en Windows, por ejemplo **WorkSpaces**, un servicio de escritorio virtual similar a Citrix. Al implementar WorkSpaces en una VPC, no solo necesita un directory service para funcionar, sino que para los file shares compartidos puede usar FSx.

### Lo que soporta como file system nativo de Windows

- **Deduplicación** (a nivel de sub-archivo).
- **DFS (Distributed File System)**, la forma en que Windows agrupa file shares y escala la estructura de archivos compartidos a nivel empresa.
- **Encryption at rest** con KMS, y la posibilidad de **forzar encryption in transit**.
- Acceso a los shares mediante el protocolo **SMB**, el estándar en entornos Windows.
- **Volume shadow copies** (snapshots de volumen), que permiten a los usuarios ver varias versiones de los archivos e iniciar restauraciones del lado del cliente. Desde Windows, hacés clic derecho en un archivo o carpeta, abrís "versiones anteriores" e iniciás la restauración a nivel de archivo sin usar AWS ni contactar a un administrador.

En rendimiento, FSx va desde **8 MB/s hasta 2 GB/s**, entrega **cientos de miles de IOPS** y ofrece **latencia inferior a 1 ms**, así que escala a cualquier requisito de rendimiento de tu organización.
