# Demostración: Splitting WordPress monolith into app and DB

🔗 <https://learn.cantrill.io/courses/1101194/lectures/27894839>

En esta demo se parte la instancia monolítica de WordPress (app + base de datos en la misma EC2) en **dos instancias**: una con la aplicación y otra con la base de datos **MariaDB**. Se exporta la base, se importa en la nueva instancia y se apunta WordPress a la IP privada de la instancia de base de datos.

### Comandos

```bash
# Backup of Source Database
mysqldump -u root -p a4lwordpress > a4lwordpress.sql

# Restore to Destination Database
mysql -h privateipof_a4l-mariadb -u a4lwordpress -p a4lwordpress < a4lwordpress.sql

# Change WP Config
cd /var/www/html
sudo nano wp-config.php
# replace:
#   /** MySQL hostname */
#   define('DB_HOST', 'localhost');
# with:
#   /** MySQL hostname */
#   define('DB_HOST', 'REPLACEME_WITH_MARIADB_PRIVATEIP');

sudo service mariadb stop
```

### Qué hace cada bloque

| Bloque | Qué pasa |
|---|---|
| `mysqldump ... > a4lwordpress.sql` | Hace un **backup** (dump) de la base `a4lwordpress` local, en la instancia original. |
| `mysql -h <IP privada> ... < a4lwordpress.sql` | **Restaura** el dump en la nueva instancia MariaDB, conectándose por su **IP privada**. |
| Editar `wp-config.php` | Cambia `DB_HOST` de `localhost` a la **IP privada de la instancia MariaDB**, para que WordPress use la base nueva. |
| `sudo service mariadb stop` | Detiene la base de datos local de la instancia original, que ya no se usa. |
