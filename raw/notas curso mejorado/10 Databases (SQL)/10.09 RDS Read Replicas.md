# RDS — Read Replicas

> [!note] Resumen de la lección
> Las **read replicas** son réplicas **de solo lectura** de una RDS instance, con **replicación asíncrona**, en la misma región o en otras. Mejoran el **rendimiento de lectura**, permiten **failover cross-region** y dan **RTOs muy bajos** (siempre que no haya corrupción de datos).

### Qué son

- Réplicas **de solo lectura**. A diferencia de la standby de multi-AZ (que no se puede usar), las read replicas sí se usan, pero solo para lecturas. (El multi-AZ cluster es como una combinación del viejo multi-AZ instance con read replicas.)
- Son **cosas separadas**: no forman parte de la primary, tienen **su propio endpoint**, y las aplicaciones tienen que ajustarse para usarlas. WordPress, por ejemplo, no sabe de ninguna read replica por defecto.
- Sin soporte de la aplicación no sirven de nada: **no hay failover automático**.

### Síncrono vs asíncrono

- **Multi-AZ → síncrona**: el dato se escribe en la primary y se replica a la standby; conceptualmente, una única operación de escritura en ambas.
- **Read replicas → asíncrona**: el dato se escribe primero en la primary (ahí queda **committed**) y **después** se replica. Puede haber **lag** (tal vez segundos), según red y cantidad de escrituras.

> [!tip] Para el examen (RDS, sin contar Aurora)
> **Síncrono = multi-AZ · Asíncrono = read replicas.**

Se pueden crear en la **misma región** o en **otras regiones** (cross-region read replicas). En cross-region, AWS gestiona la red entre regiones de forma transparente y el tráfico va **encriptado en tránsito**.

### Mejoras de rendimiento de lectura

- Hasta **5 read replicas directas** por RDS instance; cada una suma una instancia de capacidad de lectura.
- Las read replicas pueden tener **sus propias read replicas**, pero el **lag** crece (replicación asíncrona encadenada).
- Mejoran el rendimiento **global** de lectura: cargas de lectura en otras regiones se conectan a réplicas locales sin afectar a la primary.

![[Pasted image 20261002004425.png]]

### Mejoras de RPO / RTO

- **Snapshots y backups mejoran el RPO**, pero **no el RTO** (restaurar lleva mucho tiempo).
- Las read replicas dan un **RPO casi nulo** (datos sincronizados desde la primary).
- Sin corrupción de datos, se pueden **promover (promote) rápidamente** → **RTO cercano a cero**.
- Son de solo lectura **hasta que se promueven**; una vez promovidas, son una RDS instance normal.
- Forma simple de mejorar disponibilidad global: una cross-region read replica sirve como región de failover ante un problema regional de AWS.

> [!warning] Corrupción de datos
> Usá read replicas en DR **para recuperarte de una falla, no de corrupción de datos**: la read replica probablemente tenga una copia de esos datos corruptos.
