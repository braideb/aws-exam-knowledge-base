# Demostración: Migrating EC2 DB into RDS

🔗 Part 1: <https://learn.cantrill.io/courses/1101194/lectures/27894843>
🔗 Part 2: <https://learn.cantrill.io/courses/1101194/lectures/27894844>

Continuación de la [[10.02 Demostración - Splitting WordPress (app y DB)|demo anterior]]: la base de datos que quedó en la instancia EC2 con MariaDB se migra a una **RDS instance**, y WordPress se reconfigura para usar el **endpoint de RDS**.

### Comandos

```bash
# Backup of Source Database
mysqldump -h PRIVATEIPOFMARIADBINSTANCE -u a4lwordpress -p a4lwordpress > a4lwordpress.sql

# Restore to Destination Database
mysql -h CNAMEOFRDSINSTANCE -u a4lwordpress -p a4lwordpress < a4lwordpress.sql

# Change WP Config
cd /var/www/html
sudo nano wp-config.php
# replace:
#   /** MySQL hostname */
#   define('DB_HOST', 'PRIVATEIPOFMARIADBINSTANCE');
# with:
#   /** MySQL hostname */
#   define('DB_HOST', 'REPLACEME_WITH_RDSINSTANCEENDPOINTADDRESS');
```

### Qué hace cada bloque

| Bloque | Qué pasa |
|---|---|
| `mysqldump -h <IP privada MariaDB> ...` | Hace el **dump** de la base desde la instancia EC2 con MariaDB (por su IP privada). |
| `mysql -h <CNAME RDS> ... < a4lwordpress.sql` | **Restaura** el dump en la RDS instance, conectándose a su **endpoint (CNAME)**. |
| Editar `wp-config.php` | Cambia `DB_HOST` de la IP privada de MariaDB al **endpoint de la RDS instance**. |

> [!tip] Detalle
> Se usa el **endpoint DNS** de RDS, nunca una IP: el endpoint es lo que se mantiene estable ante failovers.
