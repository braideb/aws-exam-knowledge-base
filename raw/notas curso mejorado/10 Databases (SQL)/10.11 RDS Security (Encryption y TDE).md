# Amazon RDS — Security

> [!note] Resumen de la lección
> RDS soporta **cifrado en tránsito** (SSL/TLS) en todos los motores y **cifrado en reposo** con **KMS + EBS** (lo hace el **host**). Además, **SQL Server y Oracle** soportan **TDE** (cifrado dentro del motor), y **RDS Oracle** puede usar TDE con **CloudHSM**.

### Encryption in transit

En todos los motores de RDS, los datos entre el cliente y la RDS instance se pueden cifrar con **SSL/TLS**, y se puede configurar como **obligatorio** para un usuario.

### Encryption at rest (KMS + EBS)

- Se soporta de distintas formas según el motor. Por defecto, con **KMS y EBS**, gestionado por el **host de RDS** y el storage basado en EBS.
- El motor escribe datos **sin cifrar** hacia su storage; los cifra el **host** donde corre la instancia.
- Seleccionás una **CMK (Customer Master Key)** —gestionada por el cliente o por AWS— que genera **DEKs (Data Encryption Keys)**, que hacen el cifrado real.
- El **storage, los logs, las snapshots y todas las replicas** quedan cifrados con la **misma CMK**.
- El cifrado **no se puede quitar** una vez agregado.

> [!tip] Para el examen
> - El cifrado se elige **al crear la instancia**: no se puede activar ni desactivar después sobre una instancia existente.
> - Una **read replica** tiene que tener el **mismo estado de cifrado** que su primary.
> - Para cifrar una base existente sin cifrar: **snapshot → copiar la snapshot con cifrado activado → restaurar desde esa copia**.

### TDE (Transparent Data Encryption)

- Soportado por **SQL Server y Oracle**.
- El cifrado se gestiona **dentro del motor de base de datos**: los datos se cifran y descifran en el propio motor, no en el host.
- Menos confianza requerida: los datos están seguros desde que el motor los escribe en disco.

### RDS Oracle + CloudHSM

- **RDS Oracle** soporta TDE mediante **CloudHSM**.
- CloudHSM lo administrás vos, **sin exponer claves a AWS** → controles de claves más potentes.
- Permite una **cadena de confianza que no involucra a AWS**, muy valioso en situaciones regulatorias.

### Arquitectura

Una VPC con varias RDS instances sobre hosts subyacentes, usando EBS para el storage:

| Variante | Cómo funciona |
|---|---|
| **Oracle con TDE + CloudHSM** | CloudHSM provee las claves. TDE es nativo del motor: los datos se cifran desde el motor hasta el storage, **sin exponer las claves a AWS**. |
| **Cifrado basado en KMS** | KMS genera y permite usar las CMK, que generan las DEKs. Las DEKs se cargan en los hosts de RDS según haga falta y el **host** cifra/descifra. El motor no necesita soportar cifrado: escribe normal y el host cifra antes de enviar a EBS. |
| **Replicas y snapshots** | Los datos entre replicas (por ejemplo, MySQL) van cifrados, igual que las snapshots de los EBS volumes de RDS, con la **misma clave**. |
