# AWS Secrets Manager

> [!note] Resumen de la lección
> Secrets Manager comparte funcionalidad con el **SSM Parameter Store** (que con SecureStrings también guarda contraseñas), pero está diseñado específicamente para **secretos** y su diferenciador es la **rotación automática con Lambda**, con **integración directa** con productos como **RDS**. Lo principal para el examen: saber **cuándo usar uno u otro**.

Para algunas cosas, cualquiera de los dos logra el mismo resultado; no te preocupes si en ciertos escenarios no podés elegir claramente.

### Características

- Usable desde **consola, CLI, API y SDK**. Está diseñado para **integrarse dentro de otras aplicaciones** (uno de sus usos más comunes).
- **Rotación automática de secretos** con **Lambda**: una función se invoca periódicamente y actualiza los secretos.
- **Integración directa** con algunos productos, como **RDS**: además de rotar el secreto, el producto mantiene sincronizada la autenticación (la password dentro de RDS también cambia). Solo un conjunto limitado de productos lo soporta.
- Secretos **cifrados en reposo**, acceso controlado con **IAM**, rotados, y usables por los clientes para comunicarse de forma segura con, por ejemplo, una base de datos.

### Ejemplo: Catagram

1. **Catagram usa el SDK de Secrets Manager** (parte de la aplicación) para recuperar las credenciales de la base de datos.
2. El SDK usa **credenciales de IAM** para la autorización, normalmente un **rol** (access keys también, pero es menos ideal), y recupera los secretos.
3. Con los secretos, la aplicación **accede de forma segura** a la base de datos.

Hasta acá, todo esto también lo da Parameter Store (SecureStrings). Lo que diferencia a Secrets Manager:

4. **Lambda se invoca periódicamente para rotar** los secretos; en productos compatibles como RDS, la autenticación dentro de RDS también se actualiza.
5. Lambda obtiene permisos de un **execution role** de IAM, y los usa para actualizar el secreto en Secrets Manager **y** el producto integrado.

Con un producto compatible, todo queda gestionado de punta a punta. Mientras la aplicación siga consultando Secrets Manager, siempre tiene la versión más actual de los secretos.

### Seguridad con KMS

Los secretos se protegen con **KMS**: no hay riesgo de fuga por acceso físico al hardware de AWS, y KMS garantiza la **separación de funciones** — necesitás permisos **en KMS y en Secrets Manager** para acceder y descifrar.

### Secrets Manager vs SSM Parameter Store

| | Parameter Store | Secrets Manager |
|---|---|---|
| Costo | **Gratis** en tier Standard | Por **secreto** y por cada **10.000 llamadas** a la API |
| Qué guarda | Configuración y secretos | Secretos |
| Rotación automática | ❌ no rota por sí solo | ✅ con Lambda |
| Integración directa | — | **RDS / Aurora / Redshift / DocumentDB** |

> [!tip] Regla del examen
> - **Rotación automática** (sobre todo de credenciales de base de datos) → **Secrets Manager**.
> - Configuración simple o secretos sin rotación, y el costo importa → **Parameter Store**.
> - Parameter Store puede **referenciar** un secreto de Secrets Manager con el prefijo `/aws/reference/secretsmanager/`.
