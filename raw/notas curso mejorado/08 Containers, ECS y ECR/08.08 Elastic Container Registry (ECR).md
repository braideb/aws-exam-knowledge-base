# Elastic Container Registry (ECR)

ECR es un **servicio managed de registry para container images**: como Docker Hub, pero de AWS. Aloja y administra container images que se pueden usar en Docker y en otras aplicaciones de containers (pensá en **ECS** o **EKS**).

### Estructura

| Nivel | Qué es |
|---|---|
| **Registry** | Cada cuenta de AWS tiene **uno público y uno privado** |
| **Repository** | Dentro de cada registry, muchos repositories (como los repos de Git/GitHub) |
| **Container image** | Dentro de cada repository, muchas images |
| **Tag** | Cada image puede tener varios tags, **únicos dentro del repository** |

Un repository puede tener activado **tag immutability**, que impide sobrescribir un tag que ya existe (por ejemplo, subir otra image con el mismo tag `v1`). Así, cada tag siempre apunta a la misma image.

### Público vs privado

| Registry | Lectura | Escritura |
|---|---|---|
| **Public** | **Cualquiera** (read-only para todos) | Requiere permisos |
| **Private** | Requiere permisos | Requiere permisos |

### Otras características

- **Integrado con IAM** para los permisos: todo el acceso a cualquier cosa dentro del producto se controla mediante IAM.
- Además de IAM, cada repository puede tener una **repository policy** (una **resource-based policy**), que se usa, por ejemplo, para dar acceso a **otras cuentas** (cross-account).
- **Image scanning** (escaneos de seguridad de las images) en dos variantes:
  - **Basic**.
  - **Enhanced**: el tipo más nuevo, usa **Amazon Inspector**. Detecta problemas tanto en el **sistema operativo** como en cualquier **paquete de software** dentro del container, y funciona **layer por layer**.
- Métricas **near real-time** enviadas a **CloudWatch** (autenticación, operaciones de **push/pull** sobre las images).
- Registra todas las acciones de la API en **CloudTrail**.
- Genera eventos que se envían a **EventBridge**, que pueden formar parte de un workflow event-driven con container images.
- **Replicación** de container images, **cross-region** y **cross-account**.
- **Lifecycle policies**: reglas que borran images automáticamente (por ejemplo, las que no tienen tag, o las más viejas cuando se supera cierta cantidad) para no pagar storage de images que ya no se usan.

### Cómo subir una image a ECR

Es el equivalente, para ECR, del push a Docker Hub de la [[08.03 Demostración - Container of cats (Docker en EC2)|demo de container of cats]]:

```bash
# Autenticar Docker contra ECR
aws ecr get-login-password --region <region> | docker login --username AWS --password-stdin <account-id>.dkr.ecr.<region>.amazonaws.com

# Taggear la image con la URI del repository
docker tag containerofcats:latest <account-id>.dkr.ecr.<region>.amazonaws.com/containerofcats:latest

# Subir la image
docker push <account-id>.dkr.ecr.<region>.amazonaws.com/containerofcats:latest
```

| Paso | Qué pasa |
|---|---|
| `get-login-password` → `docker login` | La CLI de AWS genera un token temporal y Docker lo usa para autenticarse contra el registry (usuario `AWS`) |
| `docker tag` | El nombre de la image tiene que ser la **URI del repository**: `<account-id>.dkr.ecr.<region>.amazonaws.com/<repo>:<tag>` |
| `docker push` | Sube la image al repository |

> [!tip] Para el examen
> En un pipeline de CI/CD, este mismo flujo (login, build, tag y push) lo puede hacer **CodeBuild**. Para poder buildear images de Docker, el proyecto de CodeBuild necesita tener habilitado el **privileged mode**.
