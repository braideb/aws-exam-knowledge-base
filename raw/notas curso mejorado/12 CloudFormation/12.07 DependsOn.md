# CloudFormation DependsOn

Cuando creás una stack, CloudFormation intenta ser eficiente y hacer las cosas **en paralelo** siempre que puede. Para saber qué puede paralelizar, arma un árbol de dependencias: primero la VPC, después la subnet, después la EC2, etc. La forma principal en que deduce ese orden es mirando las **referencias**: si una EC2 referencia una subnet, y la subnet referencia una VPC, CloudFormation infiere que la VPC va primero, la subnet después y la instancia al final. A eso se le llama **dependencia implícita** (la crea, por ejemplo, un `!Ref`).

La función **DependsOn** sirve para declarar una dependencia **explícita**, cuando la implícita no alcanza. Podés decir formalmente "B y C no arrancan hasta que A esté en CREATE_COMPLETE". El árbol implícito resuelve bien el 99% de los casos; DependsOn es la herramienta para ese 1% donde hay una dependencia real que CloudFormation no puede ver por sí solo.

El ejemplo de la imagen usa una VPC, un `InternetGateway`, un `InternetGatewayAttachment` (de tipo `AWS::EC2::VPCGatewayAttachment`) y una Elastic IP (`WPEIP`):

- La VPC y el InternetGateway **se crean en paralelo**: ninguno necesita al otro para existir.
- El `InternetGatewayAttachment` lleva `VpcId: !Ref VPC` e `InternetGatewayId: !Ref InternetGateway`. Esos dos `!Ref` generan **dependencias implícitas**: el attachment no puede existir hasta que existan la VPC y el gateway (tiene sentido: para enganchar un gateway necesitás el gateway y la VPC a la que engancharlo).
- El caso **correcto** (pulgar arriba): `WPEIP` lleva `DependsOn: InternetGatewayAttachment`. Esto fuerza una **dependencia explícita**: la Elastic IP se crea **después** de que el attachment esté completo, y se elimina **antes** que él. Importa porque una EIP necesita un IGW ya enganchado a la VPC para funcionar, y esa relación no surge sola de ningún `!Ref`.
- El caso **incorrecto** (pulgar abajo): si `WPEIP` se define solo como `Type: AWS::EC2::EIP` sin DependsOn, no hay ninguna dependencia (ni implícita ni explícita), y la creación puede fallar porque la EIP se intenta crear sin el IGW todavía enganchado.
