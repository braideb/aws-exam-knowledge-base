# ARN (Amazon Resource Name)

Un **ARN** identifica **de forma única** un recurso dentro de cualquier cuenta de AWS. Sirve tanto para referirse a recursos de tu propia cuenta como de otras cuentas.

### Formato

```
arn:partition:service:region:account-id:resource-id
arn:partition:service:region:account-id:resource-type/resource-id
arn:partition:service:region:account-id:resource-type:resource-id
```

|Campo|Ejemplo|Notas|
|---|---|---|
|`partition`|`aws`|Casi siempre `aws`. Otras: `aws-cn` (China), `aws-us-gov`.|
|`service`|`s3`, `ec2`, `iam`|El servicio.|
|`region`|`us-east-1`|**Vacío** para servicios globales (S3, IAM).|
|`account-id`|`123456789012`|**Vacío** para S3 (los nombres de bucket ya son globalmente únicos).|
|`resource-id`|`catgifs`|El recurso puntual.|
Que existan tres variantes del formato no es capricho: cada servicio eligió su separador. Algunos usan `/`, otros `:`, y algunos aceptan ambos. No hay regla para deducirlo, se consulta en la documentación del servicio.

### El detalle que confunde (y que cae en el examen)

Mirá estos dos ARNs del ejemplo de policy:

```
arn:aws:s3:::catgifs      ← el BUCKET en sí
arn:aws:s3:::catgifs/*    ← los OBJETOS dentro del bucket
```

**No son lo mismo, y uno no incluye al otro.**

- El primero se refiere al bucket como entidad. Operaciones como `s3:ListBucket` (listar el contenido) aplican acá.
- El segundo se refiere a los objetos. Operaciones como `s3:GetObject` (bajar un archivo) aplican acá.

Si querés dar acceso completo, necesitás **los dos ARNs**. Es un error clásico poner solo uno y no entender por qué "no funciona".

> [!tip] Analogía `arn:aws:s3:::catgifs` es _el edificio_. `arn:aws:s3:::catgifs/*` son _los departamentos adentro_. Tener llave del portón no te da llave de los departamentos.

Los tres puntos y coma seguidos (`:::`) no son un error tipográfico: son los campos `region` y `account-id` **vacíos**, porque S3 no los usa.

### Comodines en ARNs: donde se cuela el bug de seguridad

Los ARNs aceptan `*` y `?`, y ahí hay una trampa que conviene ver una vez para no repetirla:

```
arn:aws:s3:::catgifs/*     → los objetos de catgifs. Correcto.
arn:aws:s3:::catgifs*      → catgifs, catgifs-backup, catgifs-produccion,
                             y cualquier bucket que empiece igual. Casi nunca es lo que querías.
```

La diferencia es una barra. La segunda versión otorga acceso a buckets que todavía no existen, incluyendo cualquiera que alguien cree mañana con ese prefijo.

Regla práctica: al escribir el `Resource` de una policy, leerlo en voz alta preguntándose **"¿qué otra cosa podría matchear esto?"**.

### Dónde aparecen los ARNs

No son solo cosa de policies. Se usan en:

- El campo `Resource` de identity y resource policies.
- Referencias entre servicios: el ARN del rol que ejecuta una Lambda, el ARN del topic SNS al que notifica una alarma.
- Salidas de CloudFormation (`!GetAtt MiRecurso.Arn`).
- Comandos de la CLI que piden identificar un recurso de otra cuenta.

Por eso conviene poder leerlos de un vistazo: viendo un ARN se sabe el servicio, la region, la cuenta dueña y el tipo de recurso, sin buscar nada.
