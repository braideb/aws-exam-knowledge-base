# Resumen para el examen (cheat sheet)

Repaso rápido de los datos que más se preguntan. Cada punto linkea a la sección donde está desarrollado.

- **VPC:** servicio regional, abarca todas las AZs. CIDR IPv4 de **/28 a /16**. El CIDR primario no se cambia. IPv6 opcional (**/56**). → [[05.02 Custom VPC|Custom VPC]]
- **Default VPC:** `172.31.0.0/16`, una por región, con subnets `/20` públicas por AZ e IGW ya listo. → [[01.04 Default VPC (Virtual Private Cloud) — Basics|Default VPC]]
- **Subnet:** vive en **una sola AZ**, no se puede mover. CIDR dentro del de la VPC, sin solapar. **5 IPs reservadas** por subnet (network, +1 router, +2 DNS, +3 futuro, broadcast). Bloque IPv6 = **/64**. → [[05.03 VPC Subnets|VPC Subnets]]
- **Pública vs privada:** pública = route `0.0.0.0/0` → **IGW** + IP pública. Privada = sin esa ruta; sale por **NAT**. → [[05.04 VPC Routing e Internet Gateway|Routing e IGW]]
- **Route table:** una por subnet (main o custom); gana la ruta **más específica** ([[longest-prefix-match|longest prefix match]]); la local no se borra. → [[05.04 VPC Routing e Internet Gateway#Prioridad de las routes|Prioridad de las routes]]
- **IGW:** [[region-resilient|region resilient]], 0 o 1 por VPC, NAT estático 1:1, tráfico **bidireccional**. El SO solo ve la **IP privada**. → [[05.04 VPC Routing e Internet Gateway#Internet Gateway|Internet Gateway]]
- **NAT Gateway:** en subnet **pública**, usa **Elastic IP**, **solo saliente**, [[az-resilient|AZ-resilient]] (uno por AZ para HA regional), gestionado. No sirve para IPv6 (usar [[egress-only-internet-gateway|Egress-Only IGW]]). → [[05.08 Network Address Translation (NAT) y NAT Gateway|NAT y NAT Gateway]]
- **Security Group:** en la [[eni|ENI]], [[stateful-firewall|stateful]], solo **ALLOW**, referencia otros SGs. Varios por ENI. → [[05.07 VPC Security Groups (SGs)|Security Groups]]
- **NACL:** en la **subnet**, [[stateless-firewall|stateless]] (regla para request y para response con [[ephemeral-port|ephemeral ports]]), **ALLOW y DENY**, se evalúa por número de regla. Ideal para **bloquear IPs**. → [[05.06 Network Access Control Lists (NACLs)|NACLs]]
- **VPC Endpoints:** acceso privado a servicios AWS. **Gateway** (S3/DynamoDB, gratis, ruta) vs **Interface** (PrivateLink, ENI + SG, con costo, sirve desde on-premises). → [[05.09 VPC Endpoints|VPC Endpoints]]
- **Flow Logs:** metadatos (ACCEPT/REJECT) a CloudWatch Logs/S3/Firehose. No ven el payload. → [[05.10 VPC Flow Logs|VPC Flow Logs]]
- **Lambda en VPC:** ENIs en subnets privadas + SG; pierde internet directo (NAT para salir); endpoints para servicios AWS. → [[05.11 Lambda en una VPC|Lambda en una VPC]]
- **Peering:** 2 VPCs, no transitivo, sin CIDRs solapados. Muchas VPCs → Transit Gateway. → [[05.12 VPC Peering|VPC Peering]]
- **DNS de la VPC:** IP base **+2** (y `169.254.169.253`); `enableDnsSupport` y `enableDnsHostnames` en `true` para nombres públicos y Private Hosted Zones. → [[05.02 Custom VPC#DNS en la VPC|DNS en la VPC]]

### Los números que conviene tener de memoria

| Dato | Valor |
| --- | --- |
| CIDR IPv4 de la VPC | **/16** (máximo) a **/28** (mínimo) |
| CIDR IPv6 de la VPC | **/56** fijo |
| CIDR IPv6 de la subnet | **/64** fijo |
| IPs reservadas por subnet | **5** |
| IGW por VPC | **0 o 1** |
| CIDR de la Default VPC | `172.31.0.0/16`, subnets **/20** |
| VPC del DNS Resolver | IP base de la VPC **+2** |

### Qué elegir según el escenario

| El escenario dice… | La respuesta es |
| --- | --- |
| Salida a internet desde subnet privada | **NAT Gateway** (uno por AZ para HA) |
| Salida a internet por **IPv6** | **Egress-Only Internet Gateway** |
| Llegar a **S3/DynamoDB** sin internet y sin costo | **Gateway Endpoint** |
| Llegar a un servicio AWS desde **on-premises**, o sin tocar la app | **Interface Endpoint** (PrivateLink + private DNS) |
| **Bloquear una IP** concreta | **NACL** (el SG no tiene DENY) |
| Permitir tráfico "del tier web al tier app" | **SG que referencia otro SG** ([[05.07 VPC Security Groups (SGs)#Logical references\|logical reference]]) |
| Ver **por qué** se rechaza el tráfico | **VPC Flow Logs** (`action = REJECT`) |
| Ver el **contenido** de los paquetes | **Traffic Mirroring** (no Flow Logs) |
| Conectar **2** VPCs | **VPC Peering** |
| Conectar **muchas** VPCs | **Transit Gateway** |
| Lambda que lee una **RDS privada** | Lambda **en la VPC** (subnets privadas + SG) |

> [!warning] Los cuatro errores que más se repiten
> 1. Creer que el **NAT Gateway es resiliente a nivel región**: es [[az-resilient|AZ-resilient]], hace falta uno por AZ.
> 2. Olvidar que la **NACL es stateless**: siempre hay que pensar en la regla de vuelta con [[ephemeral-port|ephemeral ports]].
> 3. Creer que el **peering es transitivo**: no lo es.
> 4. Poner una **Lambda en una subnet pública** esperando que tenga internet: nunca recibe IP pública.
