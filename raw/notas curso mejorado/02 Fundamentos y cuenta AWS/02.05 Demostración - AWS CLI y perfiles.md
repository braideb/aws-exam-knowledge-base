# Demostración: AWS CLI y perfiles

Se crean las access keys en la cuenta `iamadmin` creada anteriormente y se instala la **AWS CLI** — importante instalar la **versión 2**.

### Configurar el perfil por defecto

```bash
aws configure
```

### Configurar un perfil con nombre (named profile)

```bash
aws configure --profile iamadmin-general
```

Ambos comandos van a pedir:

- `AWS Access Key ID`
- `AWS Secret Access Key`
- `Default region name` (ej: `us-east-1`)
- `Default output format` (se puede dejar vacío)

### Usar el perfil

Si configuraste un perfil con nombre pero no lo especificas, la CLI no encuentra credenciales:

```bash
$ aws s3 ls
Unable to locate credentials. You can configure credentials by running "aws configure".
```

Hay que pasar el perfil explícitamente con `--profile`:

```bash
aws s3 ls --profile iamadmin-general
```

Y ahí sí lista los buckets:

```
2023-01-18 08:46:46 ac-catordog
2022-04-30 12:47:09 cf-templates-ul8hk0jbugwv-us-east-1
2022-08-15 08:56:26 cf-templates-ul8hk0jbugwv-us-east-2
```

> [!tip] Alternativa En vez de escribir `--profile` en cada comando, se puede exportar la variable de entorno:
> 
> ```bash
> export AWS_PROFILE=iamadmin-general
> ```

Eso vale para la sesión de terminal actual. Es cómodo, pero también es la causa del error más peligroso de la CLI: dejar exportado el perfil de producción y correr un comando destructivo creyendo que estás en desarrollo.
